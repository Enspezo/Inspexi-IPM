# B-001 — Dashboard-KPI's tonen permanent `--` (hardcoded placeholders)

- **Testgeval:** SETUP-13 (verkennend, buiten script — gevonden tijdens de setup-smoke)
- **Actor / rol:** Backoffice / MANAGER (geldt voor elke ingelogde rol)
- **App:** Portal (:5173) · org: inspexidemo
- **Severity:** S3 (matig — verwarrende UX, geen datalek of functieverlies)
- **Type:** foutgok / verkennend
- **Datum/tijd:** 2026-07-27 08:5x

## Verwacht
Het dashboard is het eerste scherm na inloggen en toont vier KPI-tegels: "Actieve inspecties",
"Gebruikers", "Openstaande taken" en "Rapporten". Verwacht: elk toont een getal, of — als de data
(nog) niet beschikbaar is — een laadindicator, een `0`, of helemaal geen tegel.

## Werkelijk
Alle vier de tegels tonen permanent `--`. Er wordt géén enkele API-call gedaan om deze waarden op
te halen: het netwerklog na login bevat alleen `auth/me`, `organizations/me/features`,
`favorites/keys`, `notifications/unread-count`, `tasks`, `notes`, `chat/unread`, `notifications` en
`audit-logs/me` — geen statistiek-endpoint.

De waarden zijn hardcoded in een module-level constante:

```tsx
// apps/portal/src/pages/dashboard/dashboard-page.tsx:16-19
const stats = [
  {
    label: 'Actieve inspecties',
    value: '--',
```

Dit geldt voor alle vier de items in de array (regels 19, 29, 39, 49). De array wordt nooit
bijgewerkt — er is geen `useQuery`, geen state, geen effect die `value` vult.

Opvallend detail: "Openstaande taken" zou triviaal te vullen zijn — de pagina haalt al
`GET /tasks?onlyMine=true&limit=100` op voor het blok "Aankomende taken" eronder, dus de data is
al in de component aanwezig.

## Reproductie
1. Log in op `http://inspexidemo.localhost:5173` als `manager@inspexi-demo.nl` / `Password123!`
2. Wacht tot het dashboard geladen is (blok "Recente activiteit" vult zich wél)
3. Kijk naar de vier tegels bovenaan → alle vier tonen `--`
4. Herladen verandert niets; wachten verandert niets

## Bewijs
- HTTP: alle calls 200; **geen** stats-endpoint aangeroepen (`read_network_requests` op `api/v1`)
- Console: geen fouten
- Code: `apps/portal/src/pages/dashboard/dashboard-page.tsx:16-56` — `value: '--'` hardcoded

## Analyse / vermoedelijke oorzaak
De tegels zijn als visuele placeholder opgeleverd en nooit aangesloten op een databron. Omdat
`stats` buiten de component staat is er ook geen plek waar de waarden ooit gezet zouden worden.
Het is geen laad- of foutafhandelingsprobleem: er wordt niets geprobeerd.

## Advies
Kies één van drie:
1. Sluit de tegels aan op echte data — "Openstaande taken" kan direct uit de reeds opgehaalde
   `useTasks()`-respons; voor de andere drie is een klein `GET /dashboard/stats`-endpoint nodig
   (org-gescoped tellingen van inspectieplannen, actieve gebruikers en rapporten).
2. Verberg de tegels tot ze data hebben.
3. Toon expliciet "nog niet beschikbaar" in plaats van `--`, zodat het geen laadfout lijkt.

Optie 1 verdient de voorkeur: het dashboard is het eerste wat elke gebruiker ziet en vier lege
tegels wekken de indruk dat het systeem niets heeft geladen.
