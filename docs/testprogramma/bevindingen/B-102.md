# B-102 — INSPECTEUR kan een gegenereerd (deels ondertekend) document hard verwijderen, inclusief alle handtekeningen

- **Testgeval:** SEC-06 (sub g)
- **Actor / rol:** Inspecteur / INSPECTEUR (`inspecteur@inspexi-demo.nl`)
- **App:** API (:3001) · org: inspexidemo
- **Severity:** S1 (blokkerend — onomkeerbaar dataverlies + autorisatie ruimer dan bedoeld)
- **Type:** autorisatie / dataverlies
- **Datum/tijd:** 2026-07-27 08:31

## Verwacht
Verwijderen van een gegenereerd inspectiedocument hoort minimaal beperkt te zijn tot de rollen die het ook mogen finaliseren (`APPROVERS` = SUPERUSER/ORG_ADMIN/MANAGER/WERKVOORBEREIDER), en een document waarop al een geldige handtekening staat (`PENDING_SIGNATURES` met een `SIGNED`-rij) zou überhaupt niet verwijderbaar mogen zijn — hooguit soft-delete/intrekken. Verwacht: **403**.

## Werkelijk
`DELETE /generated-documents/:id` staat open voor `ALL_STAFF`. De INSPECTEUR verwijderde het PLAN-document van het demo-inspectieplan (`status = PENDING_SIGNATURES`, met een reeds gezette `INSPECTOR`-handtekening van Tom Visser en een openstaand `CLIENT`-verzoek) → **HTTP 200 `{"success":true}`**.

Het is een **harde** delete (`prisma.generatedDocument.delete`), geen soft-delete: de rij is weg en de FK `imp_document_signatures.generated_document_id` cascadeert, dus **alle handtekeningen worden mee verwijderd**. Na de call stond het aantal handtekeningen van dat document op 0 en was het document niet meer terug te vinden. Er is geen audittrail-rij die de inhoud bewaart en geen herstelpad via de UI/API.

Alleen `FINALIZED` is beschermd (`"Gefinaliseerd document kan niet verwijderd worden"`) — precies de statussen daarvóór, waarin de handtekeningen worden verzameld, zijn onbeschermd.

## Reproductie
```bash
TOKEN=$(curl -s -X POST -H 'Host: inspexidemo.localhost' -H 'Content-Type: application/json' \
  -d '{"email":"inspecteur@inspexi-demo.nl","password":"Password123!"}' \
  http://localhost:3001/api/v1/auth/login | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["accessToken"])')

curl -i -X DELETE -H 'Host: inspexidemo.localhost' -H "Authorization: Bearer $TOKEN" \
  http://localhost:3001/api/v1/generated-documents/563400a1-4de7-492c-9268-7ebb4a5dae48
```

## Bewijs
- HTTP: `DELETE /generated-documents/563400a1-4de7-492c-9268-7ebb4a5dae48` → **200** `{"success":true}`
- DB vóór (`imp_generated_documents` / `imp_document_signatures`):
  ```
   563400a1-4de7-492c-9268-7ebb4a5dae48 | PLAN | PENDING_SIGNATURES
   INSPECTOR | Tom Visser  | SIGNED  | 2026-06-15 10:00:00
   CLIENT    | Demo Klant  | PENDING |
  ```
- DB ná: document weg uit `imp_generated_documents`; `SELECT count(*) FROM imp_document_signatures WHERE generated_document_id='563400a1-…'` → **0**
- Contrast: `POST /generated-documents/:id/finalize` met dezelfde INSPECTEUR → **403** `"Forbidden resource"`. Finaliseren mag níet, wegdoen wél.

> **Testdata-herstel:** de verwijderde seed-rij is met psql opnieuw opgebouwd (het door SEC-06f gegenereerde PLAN-document heeft het originele id en `generated_at` overgenomen; de twee originele handtekeningrijen zijn opnieuw ingevoegd). De originele `html_content` is niet meer identiek aan de seed maar functioneel gelijk (zelfde template).

## Analyse / vermoedelijke oorzaak
`generated-documents.controller.ts`:
```ts
@Delete('generated-documents/:id')
@Roles(...STAFF)          // STAFF = ALL_STAFF → inclusief INSPECTEUR
```
`GeneratedDocumentsService.delete()` (`generated-documents.service.ts:157`) blokkeert alleen `FINALIZED` en doet dan `this.prisma.generatedDocument.delete({ where: { id: doc.id } })` — een harde delete. `GeneratedDocument` heeft geen `isDeleted`-kolom, terwijl soft-delete elders in de codebase juist de standaard is. `imp_document_signatures` heeft `ON DELETE CASCADE`, dus getekende bewijsstukken verdwijnen zonder spoor.

## Advies
1. Zet `@Roles(...APPROVERS)` op de delete-route (gelijk trekken met `finalize`), of minimaal `REVIEW_ROLES`.
2. Verbied verwijderen zodra er één `SIGNED`-handtekening bestaat — bied in plaats daarvan "intrekken"/hergenereren aan.
3. Maak er een soft-delete van (`isDeleted` + `deletedBy`/`deletedAt`), consistent met de rest van het domein, zodat een gegenereerd rapport reconstrueerbaar blijft.
4. Neem `GeneratedDocument` en `DocumentSignature` op in `AUDITED_MODELS` zodat een verwijdering hoe dan ook in de audittrail terechtkomt.
