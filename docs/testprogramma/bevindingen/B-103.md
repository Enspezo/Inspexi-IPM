# B-103 — INSPECTEUR mag inspectiedocumenten genereren (documentgeneratie staat open voor ALL_STAFF)

- **Testgeval:** SEC-06 (sub f)
- **Actor / rol:** Inspecteur / INSPECTEUR (`inspecteur@inspexi-demo.nl`)
- **App:** API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — ruimere rechten dan het testplan aanneemt; geen datalek)
- **Type:** autorisatie / afwijking van de aanname in het testplan
- **Datum/tijd:** 2026-07-27 08:29

## Verwacht
Testgeval SEC-06 gaat ervan uit dat het inspectiedomein voor de INSPECTEUR in de portal **alleen-lezen** is: "INSPECTEUR genereert/ondertekent een rapport in de portal → geen rechten". Verwacht dus **403** op de generate-routes.

## Werkelijk
De generate-routes zijn `@Roles(...ALL_STAFF)`; de INSPECTEUR komt door de guard heen en genereert daadwerkelijk een document:
- `POST /inspection-plans/:planId/generate-plan` → **201**, er wordt een nieuw `GeneratedDocument` (type `PLAN`, status `DRAFT`) aangemaakt met volledig gerenderde `htmlContent`.
- `POST /inspection-plans/:planId/generate-report` → **404 `"Document-template niet gevonden"`** — dat is géén autorisatiestop maar een ontbrekende RAPPORT-template in deze seed. De rolcontrole werd ook hier gepasseerd; met een aanwezige template zou ook dit slagen.

Daarmee is de aanname van het testplan onjuist: genereren is bewust of onbewust opengezet voor de uitvoerende rol. Alleen `finalize` is afgeschermd (`APPROVERS`), zie SEC-06a.

Dit is op zichzelf verdedigbaar (de inspecteur maakt in de PWA het rapport), maar het combineert slecht met **B-101** (zelf ondertekenen namens elke rol), **B-104** (inhoud wijzigen ná ondertekening) en **B-102** (hard verwijderen): samen kan één INSPECTEUR de volledige documentketen alleen doorlopen, wat de vier-ogen-gedachte van PRD-13 ondergraaft.

## Reproductie
```bash
TOKEN=$(curl -s -X POST -H 'Host: inspexidemo.localhost' -H 'Content-Type: application/json' \
  -d '{"email":"inspecteur@inspexi-demo.nl","password":"Password123!"}' \
  http://localhost:3001/api/v1/auth/login | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["accessToken"])')

curl -i -X POST -H 'Host: inspexidemo.localhost' -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{}' \
  http://localhost:3001/api/v1/inspection-plans/cc495211-6b38-440c-b323-59e64a4c9af9/generate-plan

curl -i -X POST -H 'Host: inspexidemo.localhost' -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{}' \
  http://localhost:3001/api/v1/inspection-plans/cc495211-6b38-440c-b323-59e64a4c9af9/generate-report
```

- HTTP: `POST …/generate-report` → **404** `{"success":false,"message":"Document-template niet gevonden","statusCode":404}` (data-precondition, geen 403)
- Contrast binnen dezelfde controller: `POST /generated-documents/:id/finalize` → **403** `"Forbidden resource"` (`@Roles(...APPROVERS)`)

> Het in stap 1 aangemaakte document is gebruikt om de door B-102 verwijderde seed-rij te herstellen; er is geen extra testdata blijven staan.

## Analyse / vermoedelijke oorzaak
In `generated-documents.controller.ts`:
```ts
const STAFF = ALL_STAFF;
const APPROVERS = [Role.SUPERUSER, Role.ORG_ADMIN, Role.MANAGER, Role.WERKVOORBEREIDER] as const;

@Post('inspection-plans/:planId/generate-plan')   @Roles(...STAFF)
@Post('inspection-plans/:planId/generate-report') @Roles(...STAFF)
@Patch('generated-documents/:id')                 @Roles(...STAFF)
@Delete('generated-documents/:id')                @Roles(...STAFF)
@Post('generated-documents/:id/sign')             @Roles(...STAFF)
@Post('generated-documents/:id/finalize')         @Roles(...APPROVERS)   // enige uitzondering
```
Alleen `finalize` is beperkt; de rest van de lifecycle (genereren, bewerken, ondertekenen, verwijderen) is `ALL_STAFF`.

## Advies
1. Bepaal expliciet welke rollen mogen genereren en leg dat vast (PRD/documentatie), zodat testplan en implementatie samenvallen. Als de PWA-inspecteur echt moet kunnen genereren: houd `ALL_STAFF` op `generate-*`, maar…
2. …trek `PATCH`, `DELETE` en `sign` mee naar `REVIEW_ROLES`/`APPROVERS` respectievelijk een rolgebonden signer-mapping (zie B-101, B-102, B-104). Alleen dán blijft de vier-ogen-keten intact.
3. Werk de tekst van SEC-06 in `07-cross-tenant-security.md` bij naar de vastgestelde norm.
