# B-201 — Assetboom op de inspectiepagina blijft altijd leeg; geen enkele asset via de UI bereikbaar

- **Testgeval:** INS-06, INS-08 (blokkeert feitelijk INS-09 t/m INS-32 via de normale route)
- **Actor / rol:** Inspecteur / INSPECTEUR
- **App:** Inspexi-App PWA (:5176) · org: inspexidemo
- **Severity:** S2 (ernstig — het gouden pad breekt meteen na het openen van een inspectie)
- **Type:** logische fout in de boomopbouw
- **Datum/tijd:** 2026-07-27 09:02

## Verwacht
Op het inspectiedetail rendert de assetboom de assets van het plan; assets zijn klikbaar en leiden naar
het asset-detail met de tabs Overzicht/Visueel/Meetstaat/Constateringen.

## Werkelijk
De teller boven de lijst klopt ("3 Assets", "25 Assets"), maar de sectie **Assets** is volledig leeg:
geen rijen, en ook niet de lege staat "Nog geen assets". Er is geen enkele manier om via de UI een asset
te openen — alleen een handmatig getypte URL werkt. Reproduceerbaar op álle geteste plannen
(TP-RAP-001 t/m TP-RAP-004 en RAP-2026-001).

## Reproductie
1. Login als `inspecteur@inspexi-demo.nl` op `inspexidemo.localhost:5176`.
2. Inspecties → **TP Plan C — ter review (boom C, 25 assets)**.
3. Tab "Assets": de kaart toont "25 Assets" en daaronder een lege witte balk.
4. Idem voor TP Plan A (3 assets) en RAP-2026-001 (2 assets).

## Bewijs
- Screenshot: `bevindingen/img/B-201-lege-assetboom-planC.png`
- IndexedDB bevat de data wél: 39 rijen in `assetNodes`, waarvan 25 met
  `parentId = a46b76f2-… (TP Boom C — hoofdlocatie)`.
- Geen console-fouten; het is geen laad- of renderfout maar een filterfout.

## Analyse / vermoedelijke oorzaak
Twee lagen wringen:

`src/services/db/asset-nodes.ts:66` — `getAssetsByPlanId()` haalt de hele boom op en **strippped daarna
alle LOCATION-nodes**:

```ts
const nodes = await getAssetNodesForPlan(planId);
return nodes.filter((n) => n.nodeType === "ASSET").sort(...);
```

`src/features/inspection-plan/AssetTree.tsx:27` — beschouwt vervolgens alleen nodes zónder parent als
top-level:

```ts
const topLevelAssets = assets.filter((asset) => !asset.parentId);
```

In het unified AssetNode-model hangt **elke** ASSET onder een LOCATION-node, dus na het strippen heeft
iedere overgebleven node een `parentId` die niet meer in de array zit → `topLevelAssets` is altijd leeg
en er wordt niets gerenderd. De empty-state slaat niet aan omdat `assets.length` (25) niet 0 is.

Opvallend: `src/features/inspection-plan/LocationAssetTree.tsx` bestaat en rendert wél locaties én assets
gecombineerd, maar wordt **nergens geïmporteerd** — kennelijk is bij de AssetNode-cutover de verkeerde
boomcomponent blijven staan.

## Advies
1. Gebruik `getAssetNodesForPlan()` (inclusief LOCATION-nodes) als bron en render met
   `LocationAssetTree`, of
2. laat `AssetTree` de wortels afleiden i.p.v. op `!parentId` te filteren:
   `const ids = new Set(assets.map(a => a.id)); const roots = assets.filter(a => !a.parentId || !ids.has(a.parentId));`
3. Voeg een Playwright-assertie toe aan `e2e/core-flow.spec.ts` die daadwerkelijk op een `asset-row` klikt
   (de huidige happy-path-test dekt dit blijkbaar niet af).
4. Verwijder of activeer de dode component `LocationAssetTree.tsx` (zie ook B-213).

## Status (WP-B2, 2026-07-28): opgelost — PWA-PR Enspezo/InspeXi#34 (fix/wp-b2-asset-tree-ui)

> Root cause bevestigd (LOCATION-strip + `!parentId`-wortels). Structureel opgelost: het plan-detail rendert nu de volledige boom via de voorheen dode `LocationAssetTree`, gevoed door de nieuwe pure `partitionPlanNodes()` (set-gebaseerde wortel-/wees-afleiding); assets met onbekende parent verschijnen onder "Assets zonder locatie", empty-state alleen bij een écht lege boom. `AssetTree.tsx` verwijderd. Vitest `asset-node-tree.test.ts` dekt het regressiescenario; **`e2e/core-flow.spec.ts` (de repro) is groen** en `e2e/asset-tree-ui.spec.ts` klikt daadwerkelijk een `asset-row` aan.
