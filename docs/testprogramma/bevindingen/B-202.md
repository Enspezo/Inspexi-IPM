# B-202 — Asset-types worden nooit gecached (responsevorm-mismatch): "Asset toevoegen" heeft geen enkel type

- **Testgeval:** INS-09, INS-10 (blokkeert INS-11, INS-12)
- **Actor / rol:** Inspecteur / INSPECTEUR
- **App:** Inspexi-App PWA (:5176) ↔ Beheer-API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — assets aanmaken in het veld is onmogelijk, en wat er tóch wordt opgeslagen is ongeldig)
- **Type:** contract-mismatch client/server
- **Datum/tijd:** 2026-07-27 09:12

## Verwacht
De sync vult `cachedAssetTypes`; de sheet "Asset toevoegen" toont de beschikbare types (Elektrische
installatie, Zonnestroominstallatie) met hun technische velden. Zonder gekozen type is opslaan geblokkeerd
("Selecteer een type").

## Werkelijk
`cachedAssetTypes` blijft leeg (0 rijen). Onder het verplichte label "Type asset *" staat **niets**, er
zijn geen technische velden, en de parent-dropdown blijft op "-- Geen parent (top-level) --" staan.
Opslaan is desondanks mogelijk: het record wordt aangemaakt met `typeCode: ""` (zie B-203 voor het
serverzijdige gevolg).

Zodra `cachedAssetTypes` handmatig met exact dezelfde API-data gevuld wordt, werkt het scherm volledig —
de fout zit dus puur in het uitpakken van de respons.

## Reproductie
1. Login als `inspecteur@inspexi-demo.nl`; wacht de initiële sync af.
2. Open een inspectie → klik de ronde **+**-knop rechtsonder.
3. Onder "Type asset *" staat geen enkele optie.
4. Vul alleen **Naam** en sla op via het diskette-icoon in de sheet-header → het record wordt aangemaakt.
5. Console bevat: `[SyncService] No asset types in response`.

## Bewijs
- Screenshot: `bevindingen/img/B-202-asset-toevoegen-geen-types.png`
- Console (2×, StrictMode): `[warn] [SyncService] No asset types in response`
- IndexedDB `cachedAssetTypes`: `{"assetTypesCount": 0}`
- De API levert de data wél:

  ```bash
    http://localhost:3001/api/v1/asset-types
  # {"success":true,"data":[{"id":"b379f756-…","code":"electrical_installation","shortCode":"EI",
  #   "name":"Elektrische installatie","fields":[…],"parentConstraints":[]}, {…"pv_installation"…}]}
  ```
- Na handmatig injecteren van diezelfde array in `cachedAssetTypes` renderen de radio's
  "Elektrische installatie / Zonnestroominstallatie" plus de technische velden meteen correct.

## Analyse / vermoedelijke oorzaak
`src/services/sync/reference.ts:32`:

```ts
const response = await assetTypesApi.getAll();
if (response.success && response.data?.assetTypes) {
  await cacheAssetTypes(response.data.assetTypes);
} else {
  console.warn("[SyncService] No asset types in response");
}
```

`assetTypesApi.getAll()` is getypeerd als `ApiResponse<{ assetTypes: AssetTypeDefinition[] }>`, maar de
Beheer-API geeft `data` als **platte array** terug. `response.data.assetTypes` is dus `undefined` en de
cache wordt stilzwijgend overgeslagen. Dezelfde soort mismatch speelt bij de meetstaat-templates (B-205).

Daar bovenop mist `AddAssetSheet.onSubmit()` een validatie op `assetType`: het veld is in de UI met `*`
gemarkeerd, maar er is geen `required`-regel, dus een leeg type passeert.

## Advies
1. Vervang de uitpak-logica door een tolerante variant:
   `const list = Array.isArray(response.data) ? response.data : response.data?.assetTypes ?? [];`
   en corrigeer het type van `assetTypesApi.getAll()`.
2. Log een **fout** (geen `warn`) en toon de gebruiker dat de referentiedata niet geladen kon worden —
   nu faalt de app stil en lijkt de configuratie leeg.
3. Voeg `required: "Selecteer een type"` toe aan het `assetType`-veld en blokkeer opslaan bij een leeg type.
4. Voeg een contracttest toe die per referentie-endpoint de echte responsevorm valideert (dit gat is
   identiek aan B-205 en had met één gedeelde test gevangen kunnen worden).

## Status
**Opgelost** in WP-B1 — PWA-PR [Enspezo/InspeXi#32](https://github.com/Enspezo/InspeXi/pull/32) (`fix/wp-b1-reference-sync`).

- Advies 1+2: `unwrapReferenceList` accepteert de platte Beheer-array én de oude gewrapte vorm; een
  onherkenbare vorm gooit een `ReferenceSyncError` (console.error + NL-melding) die via
  `SyncResult.errors` in de rode sync-foutbanner (WP-A1) landt — geen stil lege cache meer.
- Advies 3: was bij hertest al aanwezig in `AddAssetSheet` (`required: "Selecteer een type"` + foutregel),
  toegevoegd in een eerder werkpakket; opslaan zonder type is geblokkeerd.
- Advies 4: referentie-contracttest toegevoegd (`src/services/__tests__/referenceContract.test.ts`,
  14 tests) met per endpoint de echte controller-responsevorm → assert cache gevuld.
- Browser-hertest (INS-09-acceptatie): na login-sync `cachedAssetTypes` > 0 en "Asset toevoegen" toont
  *Elektrische installatie* / *Zonnestroominstallatie* met technische velden.
