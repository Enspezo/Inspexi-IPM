# B-205 — Meetstaat-template wordt zonder secties/velden gecached: meetstaat toont geen enkel invoerveld (en crasht op serverrecords)

- **Testgeval:** INS-20 (blokkeert INS-21 t/m INS-26)
- **Actor / rol:** Inspecteur / INSPECTEUR
- **App:** Inspexi-App PWA (:5176) ↔ Beheer-API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — metingen vastleggen is niet mogelijk)
- **Type:** contract-mismatch (list- vs. detail-respons) + onafgevangen TypeError
- **Datum/tijd:** 2026-07-27 09:25

## Verwacht
De meetstaat toont de secties en velden van template `MS-NEN1010-ISO` (sectie "Isolatieweerstand" met de
velden `group` en `r_iso`), zodat de inspecteur metingen kan invoeren.

## Werkelijk
**Deel 1 — geen velden.** De meetstaatpagina toont kop, voice-balk, meetmiddelen en "Afronden", maar
**geen enkele sectie of rij**. De statusregel meldt misleidend "100% voltooid · 0 Pass · 0 Fail · 0 Open".
Oorzaak: de PWA cachet de *lijst*-respons van `/measurement-sheet-templates`, en die bevat geen `sections`
(alleen `_count`). De detail-route levert ze wél.

**Deel 2 — crash.** Zodra de cache wél secties bevat (handmatig gevuld met de detail-respons) en de asset
een **door de server aangemaakt** meetstaat-record heeft, crasht de pagina:

> Fout bij het laden van de meetstaat
> `TypeError: Cannot read properties of undefined (reading 'isolation')` — `measurementSheetService.ts` → `validateRecord` → `MeasurementSheetPage.loadData`

De server bewaart `data` als `{"isolation": {...}}`, de PWA verwacht `{"sections": {"isolation": {...}}}`.
`asRecordData()` is een pure cast zonder controle, dus `recordData.sections[section.code]` gooit.

## Reproductie
**Deel 1**
1. Login als `inspecteur@inspexi-demo.nl`.
2. Open `/inspections/cc495211-…/assets/1fde2f90-…/measurement-sheet`.
3. Geen invoervelden; teller zegt 0 Pass / 0 Fail / 0 Open.

**Deel 2**
4. Vul `cachedMeasurementSheetTemplates` met `GET /measurement-sheet-templates/f2a4706a-…` (mét `sections`).
5. Herlaad dezelfde pagina → "Fout bij het laden van de meetstaat" + de bovengenoemde TypeError.

## Bewijs
- Screenshot: `bevindingen/img/B-205-meetstaat-zonder-velden.png`
- Gecachte template: `{"code":"MS-NEN1010-ISO","sections":[]}` → `hasSections: false`
- API-vergelijking:
  ```
  GET /measurement-sheet-templates       → keys: … 'finalCheckRules','_count'          (géén sections)
  GET /measurement-sheet-templates/:id   → keys: … 'sections' → 1 sectie, fields ['group','r_iso']
  ```
- Serverzijdige recorddata (psql):
  ```
  {"isolation": {"0": {"group": {"value":"Groep 1","passFail":null},
                       "r_iso": {"value":210.5,"passFail":"pass"}}, …}}
  ```
  PWA-zijdige recorddata: `{"sections":{"isolation":{"rows":[{"r_iso":2.5,"group":"Groep 1"}]}}}`
- Console: `[MeasurementSheet] ❌ Failed to load: TypeError: Cannot read properties of undefined (reading 'isolation') at validateRecord (…/measurementSheetService.ts:245:44)`

## Analyse / vermoedelijke oorzaak
`src/services/sync/reference.ts` → `fetchAndCacheMeasurementSheetTemplates()` cachet de lijst met de
comment *"Transform to cached format with sections included"*, terwijl de lijst-endpoint die secties niet
meelevert. Zonder secties valt `validateRecord()` meteen terug op `if (!template.sections) return result;`
— dat maskeert deel 2 en verklaart de "100% voltooid"-melding bij 0 velden.

Deel 2 is een echte contractdivergentie tussen de twee schrijvers van `MeasurementSheetRecord.data`
(server/portal vs. PWA). Beide vormen bestaan naast elkaar in de database.

## Advies
1. Cache per template de **detail**-respons (of breid de lijst-endpoint uit met `sections`), en valideer
   na het cachen dat elke template ≥1 sectie heeft — log anders expliciet.
2. Kies één canonieke vorm voor `MeasurementSheetRecord.data` en migreer de bestaande rijen; leg de vorm
   vast in het v3-contract (`sheetRecordDataSchema` bestaat al server-side — laat die de bron van waarheid zijn).
3. Maak `asRecordData()` defensief (`data?.sections ?? {}`) zodat een afwijkende vorm hooguit tot een lege
   weergave leidt en niet tot een crash-scherm.
4. Toon niet "100% voltooid" wanneer er nul velden zijn; toon dan "template bevat geen velden".

### Deel 2 — WP-D2 (besluit A2, 28-07-2026): servervorm canoniek

- **Canonieke vorm** (vastgelegd + afgedwongen; zie `docs/fase3/FASE3-SYNC.md` §11):
  `{ [sectionCode]: { [rijnummer]: { [fieldCode]: { value, passFail } } } }` — niet-
  herhalende secties zijn rij `"0"`; top-level `__`-sleutels (bv.
  `__usedInstrumentsSnapshot`) zijn gereserveerde server-metadata.
- **Advies 2 uitgevoerd**: `sheetRecordDataSchema` is nu een écht schema (niet langer
  het permissieve `jsonObjectSchema`) en wordt afgedwongen op REST-`PATCH`, de
  `/sync`-push én `/sync/resolve`. De verouderde PWA-vorm (`sections`-wrapper) geeft
  een gerichte NL-melding. Contract blijft **v4** (de vorm wás al de gedocumenteerde
  wire-vorm; de wrapper was een client-afwijking — onderbouwing in §11.4).
- **Datamigraties**: server `20260728100000_canonicalize_sheet_record_data` (records +
  openstaande sync-conflictpayloads; idempotent; `updated_at` onaangeraakt tegen valse
  v4-conflicten) · PWA Dexie **v17→v18** (lokale records incl. pending + bewaarde
  conflict-snapshots in `syncRetryMeta`).
- **PWA schrijft/leest canoniek**: `measurementSheetData.ts`/`measurementSheetService.ts`
  zijn canonical-native herschreven (de runtime-vorm valt nu samen met de gedeelde
  typedef `MeasurementSheetRecordData`); pass/fail wordt bij elke save tegen de
  bevroren snapshot geëvalueerd (zoals de server bij REST-updates doet). De
  WP-B1-crashguard in `asRecordData()` is vervangen door een transitionele
  legacy→canoniek-conversie (gemarkeerd als transitie-code).
- **Restrisico (klein)**: uit de legacy-vorm gemigreerde waarden dragen
  `passFail: null` (de oude vorm sloeg nooit een pass/fail-uitkomst op); de uitkomst
  wordt bij de eerstvolgende bewerking/save opnieuw geëvalueerd. Een pre-D2-app die
  nog de oude vorm pusht krijgt een nette per-record-fout en herstelt zichzelf na de
  app-update (v18-migratie → re-push).

- Advies 1: Beheer-lijst-endpoint uitgebreid met `?include=sections` (secties + velden, geen N+1); de
  PWA vraagt die param en valt op een oudere backend per template terug op de detail-route (beperkte
  parallelliteit). Na het ophalen wordt per template gevalideerd dat er secties zijn; een lege template
  wordt expliciet als fout gelogd.
- Advies 3 (deel 2, **stopgap** — géén D2-beslissing): `asRecordData()` is defensief gemaakt in de ene
  gedeelde bron `services/measurementSheetData.ts` (de private duplicaat in `measurementSheetService.ts`
  is daarop samengevoegd). Server-vormige recorddata (`{isolation: …}`) leidt nu tot een lege weergave
  i.p.v. de TypeError-crash. Bestaande serverwaarden worden dus (nog) niet getoond of geconverteerd.
- Advies 4: `getCompletionPercentage` geeft 0 (niet 100) bij nul velden en de meetstaatpagina toont
  "Template bevat geen velden".
- Advies 2 (canonieke vorm + migratie van bestaande rijen + vastleggen in het v3-contract) is bewust
  **niet** in WP-B1 gedaan: dat is het beslispunt van **WP-D2**. Restrisico tot die tijd: records
  waarvan de inspecteur na de fix velden invult dragen een gemengde vorm
  (`{oude-serverkeys…, sections: {…}}`); de server accepteert dit (generiek JSON-schema).
- Browser-hertest (INS-20-acceptatie): meetstaat op het demo-plan rendert sectie "Isolatieweerstand"
  met de velden `group`/`r_iso`, zonder crash en zonder misleidende "100% voltooid".
