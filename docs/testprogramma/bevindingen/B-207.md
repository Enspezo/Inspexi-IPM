# B-207 — Meetstaat-records synchroniseren nooit: verplichte `templateVersion` ontbreekt in de push (stil dataverlies)

- **Testgeval:** INS-26 (raakt INS-20 t/m INS-25)
- **Actor / rol:** Inspecteur / INSPECTEUR (`inspecteur@inspexi-demo.nl`)
- **App:** Inspexi-App PWA (:5176) → Beheer-API (:3001) · org: inspexidemo
- **Severity:** S1 (blokkerend — dataverlies bij sync)
- **Type:** sync-contract / ontbrekend verplicht veld
- **Datum/tijd:** 2026-07-27 09:31

## Verwacht
Een in het veld ingevulde en afgeronde meetstaat wordt bij de sync naar de server gepusht en is daarna
in de portal zichtbaar bij de asset.

## Werkelijk
`POST /sync/push` weigert **elk** meetstaat-record dat de PWA aanmaakt, omdat Prisma het verplichte veld
`templateVersion` mist. De PWA stuurt wel `templateSnapshot` (waarin `version: "1.0"` zit), maar niet het
losse kolomveld. Gevolg: geen enkel in de PWA ingevuld meetstaat-record bereikt ooit de server; de
records blijven pending en de fout is voor de inspecteur onzichtbaar (B-211).

Dit geldt zowel voor `IN_PROGRESS`- als voor afgeronde (`COMPLETED`) records.

## Reproductie
1. Login als `inspecteur@inspexi-demo.nl`.
2. *(Harness, zie B-205: vul `cachedMeasurementSheetTemplates` met de detail-respons zodat er velden zijn.)*
3. Open `/inspections/0c46d844-…/assets/d133d967-…/measurement-sheet`.
4. "+ Rij toevoegen", vul `Groep` en `Isolatieweerstand = 2,5`, klik **Afronden**.
5. Klik het sync-pilletje.
6. `psql -c "SELECT * FROM imp_measurement_sheet_records WHERE asset_node_id='d133d967-…'"` → **0 rows**.

## Bewijs
- `POST /api/v1/sync/push` → **201**, `processed.measurementSheetRecords: 0`, en in `errors[]`:
  ```
  Invalid `model.create()` invocation in
  /Users/mathijs/VIBE/InspeXi-Beheer-test/apps/api/src/modules/sync/sync.service.ts:546:19
    → 546 await model.create({ data: { templateId: "f2a4706a-…", assetNodeId: "d133d967-…",
            … status: "COMPLETED", data: { sections: { isolation: { rows: [ { r_iso: 2.5,
            group: "Groep 1 — 日本語 <b>vet</b>" } ] } } }, …
        +   templateVersion: String
          } })
  Argument `templateVersion` is missing.
  ```
  (Twee records faalden identiek: `34597f83-…` COMPLETED en `b4b812cd-…` IN_PROGRESS.)
- DB-verificatie: `SELECT id FROM imp_measurement_sheet_records WHERE asset_node_id='d133d967-…'` → 0 rijen.
- Console: alleen `[SyncContext] ❌ Sync completed with errors: Array(2)`; UI toont uitsluitend het
  amberkleurige pending-pilletje.

## Analyse / vermoedelijke oorzaak
De Prisma-model `MeasurementSheetRecord` heeft `templateVersion` als **verplichte** kolom, maar
`templateVersion` staat niet in de payload die de PWA opbouwt (`measurementSheetService` /
`sync/push.ts`), en de sync-mapper vult geen default. De REST-route van de Beheer-API zet het veld
waarschijnlijk zelf, waardoor het gat pas via het sync-pad zichtbaar wordt — en daar ontbreekt de
e2e-dekking (het record wordt in bestaande tests kennelijk niet via `/sync/push` aangemaakt).

Merk op dat de PWA en de server bovendien een **verschillende datavorm** hanteren: de PWA schrijft
`{sections:{isolation:{…}}}`, de serverzijdige (geseede/portal-)records staan als `{isolation:{…}}`.
Zie B-205 voor het crash-effect dat dat oplevert.

## Advies
1. Vul `templateVersion` in de push-payload (uit `templateSnapshot.version`), of maak het veld
   server-side afleidbaar/optioneel met een default in `sync.service`.
2. Voeg een e2e-test toe die exact het PWA-pad afdekt: `POST /sync/push` met een
   `measurementSheetRecords`-create, en assert dat het record daadwerkelijk in de DB staat.
3. Harmoniseer de `data`-vorm tussen PWA en server (zie B-205) en leg die vast in het v3-contract.
4. Maak push-fouten zichtbaar in de UI (B-211) zodat dit soort contractbreuk in het veld niet stil blijft.

## Status
**Opgelost** (WP-A2 — PWA-PR `fix/wp-a2-data-loss-stop` + Beheer-PR `fix/wp-a2-sync-contract-tests`).
Root cause bevestigd: `getOrCreateMeasurementSheetRecord` zette `templateVersion` nooit; de
push-serializer stripte `undefined` weg en Prisma weigerde elk record.

- **PWA:** `templateVersion: templateSnapshot.version` wordt bij create gezet; het veld is uit de
  `Partial<…>` in `services/db/types.ts` gehaald zodat TypeScript het afdwingt. De push-serializer
  normaliseert de waarde naar een string (de serverkolom is `String`, de gedeelde typedef zegt ten
  onrechte `number`). **Dexie v15-repair** vult op bestaande toestellen een ontbrekende
  `templateVersion` uit `templateSnapshot.version`, anders bleef het dataverlies daar bestaan.
- **Beheer:** `measurementSheetRecords` heeft nu `requiredOnCreate` (templateId/templateVersion/
  templateSnapshot) → nette NL-melding "Template-versie ontbreekt" i.p.v. de rauwe Prisma-tekst, en
  een numerieke `templateVersion` uit oudere caches wordt verliesvrij naar string gecoerced.
  Advies 2 is de nieuwe sync-contractsuite `apps/api/test/sync-contract.e2e-spec.ts` (PWA-vormige
  payload → push → DB-rij, plus de regressie zónder templateVersion).
- Advies 3 (datavorm `{sections:{…}}`) valt onder WP-B1/B-205; het contract-e2e legt de PWA-vorm
  alvast als geaccepteerde wire-vorm vast. Advies 4 was WP-A1.
