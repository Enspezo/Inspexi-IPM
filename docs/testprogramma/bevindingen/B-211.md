# B-211 — Mislukte sync blijft onzichtbaar: de rode banner "Synchronisatie mislukt" wordt direct overschreven door de statuspoll

- **Testgeval:** INS-16, INS-26, INS-41 (versterkt B-206, B-207)
- **Actor / rol:** Inspecteur / INSPECTEUR
- **App:** Inspexi-App PWA (:5176) · org: inspexidemo
- **Severity:** S2 (ernstig — de inspecteur krijgt geen enkel signaal dat zijn werk niet is aangekomen)
- **Type:** state-race in de UI
- **Datum/tijd:** 2026-07-27 10:08

## Verwacht
Wanneer de server een of meer records weigert, toont de app de rode banner
"Synchronisatie mislukt" met de knop "Probeer opnieuw" (de banner bestaat en is correct opgebouwd in
`Layout.tsx:152`).

## Werkelijk
De banner verschijnt niet. Na een push waarin de server records weigert, ziet de inspecteur uitsluitend het
amberkleurige pending-pilletje met het aantal openstaande wijzigingen — visueel identiek aan "nog even
wachten". Alleen de developer-console verraadt het probleem:
`[SyncContext] ❌ Sync completed with errors: Array(1)`.

Gecombineerd met B-206 en B-207 betekent dit dat álle constateringen en meetstaten die een inspecteur
vastlegt, permanent en volledig geruisloos in de wachtrij blijven staan.

## Reproductie
1. Volg de reproductie van B-206 (constatering aanmaken) of B-207 (meetstaat afronden).
2. Klik het sync-pilletje.
3. Console: `[SyncContext] ❌ Sync completed with errors: Array(n)`.
4. UI: geen rode banner, geen toast, geen markering bij het record — alleen "n" in het pilletje.

## Analyse / vermoedelijke oorzaak
De keten klopt op zich: `syncAll()` geeft `success: errors.length === 0` (`services/sync/index.ts:410`),
`SyncContext` zet vervolgens `setLastSyncResult(result)` en `setSyncState("error")`.

Het probleem is het periodieke statuseffect:

```ts
useEffect(() => {
  async function checkStatus() { … 
    if (!isOnline)                    setSyncState("offline");
    else if (syncState === "syncing") return;
    else if (progress.hasPendingChanges) setSyncState("pending");
    else                              setSyncState("synced");
  }
  checkStatus();
  const interval = setInterval(checkStatus, 30000);
}, [isOnline, syncState]);        // <-- draait opnieuw zodra syncState verandert
```

Omdat `syncState` zélf in de dependency-array staat, draait `checkStatus()` direct nadat de state op
`"error"` is gezet. Er zijn per definitie nog pending changes (de geweigerde records!), dus
`setSyncState("pending")` overschrijft de foutstatus binnen dezelfde tick en de bannerconditie
`syncState === "error"` is nooit waar wanneer de gebruiker kijkt.

Bijkomend: er is ook geen markering op recordniveau — een record met `syncRetryMeta.status = "failed"`
ziet er in de lijsten net zo uit als een record dat gewoon nog in de wachtrij staat.

## Advies
1. Laat `checkStatus()` de `error`-status niet overschrijven (`if (syncState === "error") return;` of
   een aparte `lastSyncFailed`-vlag die pas bij een geslaagde sync wordt gewist).
2. Haal `syncState` uit de dependency-array en gebruik een functionele update, zodat de poll geen
   state-races veroorzaakt.
3. Toon per record een zichtbare foutstatus zodra `syncRetryMeta.status === 'failed'` (bijv. een rood
   badge-icoontje bij de constatering/meetstaat) met de servermelding erachter.
4. Voeg een "dead letter"-drempel toe: na N mislukte pogingen een blokkerende melding in plaats van
   stil doorretryen.
