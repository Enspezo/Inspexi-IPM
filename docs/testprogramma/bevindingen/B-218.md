# B-218 — Indienen via `/sync/push` stuurt geen `INSPECTIEPLAN_TER_REVIEW`-notificatie: de beoordelaar hoort niets

- **Testgeval:** INS-35
- **Actor / rol:** Inspecteur / INSPECTEUR
- **App:** Inspexi-App PWA (:5176) → Beheer-API (:3001) · org: inspexidemo
- **Severity:** S3 (matig — de data klopt, maar de review-keten start niet vanzelf)
- **Type:** ontbrekende dispatch in het sync-pad
- **Datum/tijd:** 2026-07-27 09:39

## Verwacht
Na het indienen vanuit de afrond-wizard verschijnt het plan in de portal én krijgt de beoordelaar een
notificatie (scriptverwachting INS-35: "Data verschijnt in Portal; reviewer krijgt notificatie").

## Werkelijk
De statuswijziging komt correct op de server (`status = pending_review`, `submitted_at` gezet), maar er
wordt **geen** notificatie aangemaakt. Het REST-pad `InspectionPlansService.submit()` dispatcht wél
`INSPECTIEPLAN_TER_REVIEW` (regel 547); het sync-pad kent die stap niet. Consequentie: een plan dat via de
PWA is ingediend blijft in de wachtrij hangen tot iemand de portal toevallig raadpleegt.

Bijkomend: het geteste plan had `reviewer_id = NULL`, dus er is ook geen geadresseerde. De wizard vraagt
niet om een beoordelaar en de sync vult er geen in.

Waarschijnlijk wordt om dezelfde reden ook de automatische **AI-voorcontrole** (PRD-13, `startRun` bij
`submit()`) overgeslagen bij een PWA-indiening — niet apart geverifieerd (de org heeft `ai_review_enabled = true`).

## Reproductie
1. Login als `inspecteur@inspexi-demo.nl`, rond een asset af, open "Inspectie afronden".
2. Doorloop de wizard en klik "Indienen ter beoordeling".
3. Synchroniseer.
4. ```sql
   SELECT reference_number, status, submitted_at, reviewer_id
   FROM imp_inspection_plans WHERE id='0c46d844-…';
   -- TP-RAP-001 | pending_review | 2026-07-27 07:39:31.944 |          <-- reviewer leeg

   SELECT type, title, user_id, created_at FROM imp_notifications ORDER BY created_at DESC LIMIT 5;
   -- geen enkele INSPECTIEPLAN_*-rij; nieuwste rijen zijn OFFERTE_/MILESTONE_-notificaties van eerder
   ```

## Bewijs
- Statuswijziging geland (zie query hierboven).
- Geen nieuwe rij in `imp_notifications` na het indienen.
- Codebewijs: `grep -rn "INSPECTIEPLAN_TER_REVIEW" apps/api/src/` → alleen
  `inspection-plans.service.ts:115` (definitie) en `:547` (dispatch); **geen** treffer in
  `modules/sync/`.

## Analyse / vermoedelijke oorzaak
`sync.service.ts` gebruikt een generieke mutator die whitelisted velden wegschrijft. Alleen chat-entiteiten
worden bewust naar hun eigen service gedelegeerd ("ze vereisen membership-autorisatie + notificatie-dispatch",
comment op regel 418). Voor inspectieplannen is die delegatie er niet, dus de statusovergang
`in_progress/draft → pending_review` mist alle side-effects van `submit()`.

## Advies
1. Delegeer een statusovergang naar `pending_review` in de sync naar `InspectionPlansService.submit()`
   (of roep minimaal dezelfde `notify()` + AI-review-start aan), zodat REST en sync identiek gedrag geven.
2. Val bij een lege `reviewerId` terug op dezelfde ontvangerbepaling als elders (projectmanager →
   reviewer → assignedTo), zodat er altijd een geadresseerde is.
3. Voeg een e2e-test toe die het volledige PWA-indienpad afdekt inclusief notificatie en AI-run.
