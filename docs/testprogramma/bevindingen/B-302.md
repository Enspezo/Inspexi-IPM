# B-302 — Grenswaarden op offerteregels worden alleen door native browservalidatie geblokkeerd (Engelse melding); de backend accepteert alles

- **Testgeval:** BO-04, BO-14, BO-15, BO-16, BO-20
- **Actor / rol:** Backoffice / MANAGER
- **App:** Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S3 (matig — ontbrekende servervalidatie + verwarrende/Engelse melding)
- **Type:** grenswaarde / foutgok
- **Datum/tijd:** 2026-07-27 10:50

## Verwacht
Bij een negatieve eenheidsprijs, korting > 100% of btw > 100% verwacht je een **Nederlandse
veldfout in de applicatie** (zoals bij "Titel is verplicht" in de aanvraagmodal), en een backend die
onzinnige waarden weigert of bewust als creditregel toelaat mét UI-indicatie.

## Werkelijk
De offerte-editor gebruikt uitsluitend **native HTML5-constraints** (`min=0` op eenheidsprijs,
`max=100` op korting en btw) binnen één `<form>`. Gevolg:

1. Bij een ongeldige waarde doet "Opslaan" **niets zichtbaars**: er verschijnt geen in-app foutmelding,
   alleen een vluchtige native browserbubbel in de **taal van de browser** (hier Engels):
   ```
   Value must be greater than or equal to 0.
   Value must be less than or equal to 100.
   ```
   Precies hetzelfde geldt voor de relatie-modal: `E-mail = geen-email` (`input[type=email]`) →
   `"Please include an '@' in the email address. 'geen-email' is missing an '@'."`
2. De **backend heeft geen enkele grens**. Alle onderstaande calls slagen met **HTTP 200**:

| Invoer (`PUT /api/v1/quotes/:id/lines`) | Status |
|---|---|
| `unitPrice: -100` | 200 |
| `discountPct: 150` | 200 |
| `vatRate: 250` | 200 |
| `vatRate: -50` | 200 |
| `quantity: 0` / `0.001` | 200 |
| `quantity: -1` | **400** ✔ (`quantity must not be less than 0`) |
| `unitPrice: "NaN"` (string) | **400** ✔ |

3. Het gevolg is bedrijfsmatig onzin. De seed-offerte `TP-OFF-010` staat er vol mee en UI én backend
   tonen exact dezelfde (interne consistente) waarden: subtotaal **€ -350,00**, korting **-€ 750,00**,
   btw **€ 155,50**, totaal **€ -194,50**. Zelf ingevoerd: `unitPrice -100` × `qty 2` met `korting 150%`
   levert een **positief** regeltotaal van € 100,00.
4. `NaN` / `Infinity` / `1.79e309` in een `input[type=number]` worden door de browser gewist (veld → `0`),
   dus er komt géén NaN in het totaal. `1e9` wordt wél geaccepteerd (regeltotaal € 2.000.000.000,00).

**Positief:** UI-totalen en backend-totalen komen exact overeen; er is geen rekenafwijking tussen beide.

## Reproductie
1. Login `manager@inspexi-demo.nl`, open een CONCEPT-offerte → **Bewerken**.
2. Zet op regel 1: eenheidsprijs `-100`, korting `150`, btw `250` → **Opslaan**.
3. Er gebeurt niets zichtbaars; `document.querySelectorAll('main input')` met `checkValidity()===false`
   levert de drie Engelse meldingen hierboven.
4. Dezelfde waarden via de API (`PUT /api/v1/quotes/:id/lines`) → **200 OK**, opgeslagen.

## Bewijs
- HTTP-statussen zoals in de tabel hierboven (via `curl`, `NODE_ENV=test`).
- Console: geen JS-fouten.
- DB: `imp_quote_lines` van `TP-OFF-010` bevat `unit_price -100.00`, `discount_pct 150`, `vat_rate 250`.

## Analyse / vermoedelijke oorzaak
`SetQuoteLinesDto`/`QuoteLineDto` heeft alleen `@Min(0)` op `quantity`; `unitPrice`, `discountPct` en
`vatRate` hebben geen `@Min`/`@Max`. De frontend leunt op `min`/`max`-attributen, die (a) een
niet-gelokaliseerde bubbel geven en (b) triviaal te omzeilen zijn via de API.

## Advies
- Voeg `@Min(0)` op `unitPrice` (of sta negatief expliciet toe als creditregel), `@Min(0) @Max(100)` op
  `discountPct` en een realistische `@Min(0) @Max(100)` op `vatRate` toe aan de DTO.
- Vervang de native constraints door zod-veldfouten in het Nederlands, zoals de aanvraagmodal al doet.

## Status
**Opgelost in WP-B5** (branch `fix/wp-b5-quote-chain`).
- Backend: `QuoteLineDto` heeft nu `@Min(0)`/`@Max` op `unitPrice` (0 – 9.999.999,99), `@Min(0) @Max(100)` op `discountPct` én `vatRate`, en `@Max(9.999.999,99)` op `quantity` — alle met Nederlandse meldingen (`apps/api/src/modules/quotes/dto/set-quote-lines.dto.ts`).
- Portal: de offerte-editor staat op `noValidate` en valideert de regels bij Opslaan met Nederlandse veldfouten (rode rand + melding per veld) i.p.v. de native Engelse browserbubbels (`apps/portal/src/pages/quotes/quote-editor-page.tsx`).
- Seed-fixture `TP-OFF-010` is aangepast naar waarden exact óp de nieuwe grenzen (prijs € 0,01, korting 100%, btw 100%) en blijft daarmee het herkenbare randgeval (`apps/api/prisma/seed-tp/beheer.ts`).
- De e-mail-bubbel in de relatie-modal (native `input[type=email]`) valt buiten dit werkpakket.
