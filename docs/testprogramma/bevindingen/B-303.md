# B-303 — HTTP 500 "Internal server error" zodra een offertetotaal `numeric(12,2)` overschrijdt

- **Testgeval:** BO-17 (grote aantallen), BO-20
- **Actor / rol:** Backoffice / MANAGER
- **App:** Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — 500 op invoer die de UI zelf toestaat; orakel "geen 500" geschonden)
- **Type:** grenswaarde
- **Datum/tijd:** 2026-07-27 10:52

## Verwacht
Een groot aantal (`999999999`) is volgens het script toegestaan (`@Min(0)`, geen max) en mag "geen
overflow in de weergave" geven. In elk geval: **nooit een HTTP 500** — hooguit een nette 400 met een
Nederlandse melding dat het bedrag te groot is.

## Werkelijk
Zodra regeltotaal, subtotaal, btw of totaal boven `numeric(12,2)` (max **9.999.999.999,99**) uitkomt,
gooit Postgres `numeric field overflow` en geeft de API **HTTP 500**:

```
{"success":false,"message":"Internal server error",
 "requestId":"a1ac7291-2bf0-40eb-ab6b-c5c8a0f3269d","statusCode":500}
```

Gemeten grenzen (`PUT /api/v1/quotes/:id/lines`):

| Regel | Status |
|---|---|
| `quantity 999999999`, `unitPrice 1` (totaal 999.999.999) | 200 ✔ |
| `quantity 999999999`, `unitPrice 100` | **500** |
| `quantity 99999999`, `unitPrice 100` (totaal incl. btw ≈ 12,1 mld) | **500** |
| `unitPrice 100000000000` (1e11) | **500** |

De invoer is **volledig bereikbaar vanuit de UI**: het aantal-veld heeft alleen `min=0`, geen `max`.
Een gebruiker die `999999999` typt en op Opslaan klikt, krijgt de rauwe, **Engelse** toast
"Internal server error". De offerte zelf blijft ongewijzigd (goed), maar er is geen bruikbare
foutmelding en het formulier springt terug naar de geladen waarden.

## Reproductie
1. Login `manager@inspexi-demo.nl`, open een CONCEPT-offerte → **Bewerken**.
2. Zet op de eerste regel: aantal `999999999`, eenheidsprijs `100`.
3. Klik **Opslaan** → rode toast **"Internal server error"**.
4. Identiek via API: `PUT /api/v1/quotes/:id/lines` met dezelfde waarden → **500**.

## Bewijs
- HTTP: `PUT /api/v1/quotes/b97f1d02-…/lines` → **500** (requestId in de body)
- DB-bevestiging van de oorzaak:
  ```sql
  select 12099999879.00::numeric(12,2);
  -- ERROR: numeric field overflow
  -- DETAIL: A field with precision 12, scale 2 must round to an absolute value less than 10^10.
  ```
- Kolommen `imp_quote_lines.line_total`, `imp_quotes.subtotal/vat_total/total` zijn alle `numeric(12,2)`.
- Screenshot: `bevindingen/img/B-303-500-numeric-overflow.png`
- Console: geen JS-fouten; alleen de 500-toast.

## Analyse / vermoedelijke oorzaak
De berekende bedragen worden ongefilterd naar Prisma/Postgres geschreven. Er is geen bovengrens in de
DTO en geen afvang van `PrismaClientKnownRequestError` (numeric overflow) in de quotes-service, dus de
Prisma-fout valt door naar de generieke 500-handler.

## Advies
- Voeg een `@Max` toe aan `quantity` en `unitPrice` in `QuoteLineDto` (bv. 1e7 resp. 1e8), en/of
- valideer het berekende totaal vóór de write en geef een 400 met een NL-melding
  ("Het offertetotaal is te groot; maximaal € 9.999.999.999,99").
- Vang numeric-overflow in de service af en vertaal naar 400 i.p.v. 500.
