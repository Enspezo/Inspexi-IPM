# B-304 — Offerte boven de goedkeuringsdrempel is via de portal niet ter goedkeuring in te dienen (dead-end)

- **Testgeval:** BO-23, BO-24
- **Actor / rol:** Backoffice / MANAGER (en BACKOFFICE)
- **App:** Portal (:5173) · org: inspexidemo (drempel € 10.000, rol MANAGER)
- **Severity:** S2 (ernstig — het gouden pad "offerte > drempel versturen" is via de UI onmogelijk)
- **Type:** ontbrekende UI-actie / procescyclus
- **Datum/tijd:** 2026-07-27 11:00

## Verwacht
Volgens BO-24: `CONCEPT → TER_GOEDKEURING → GOEDGEKEURD → VERSTUURD`. Op een CONCEPT-offerte boven de
org-drempel hoort een actie **"Ter goedkeuring"** te staan die `POST /quotes/:id/submit-approval`
aanroept.

## Werkelijk
Voor een offerte van **€ 30.250** op het standaardsjabloon (`requiresApproval = false`) toont de
actiemenu-knop alleen:

- **Goedkeuren** → `POST /quotes/:id/approve` → **400** "Alleen offertes met status TER_GOEDKEURING kunnen goedgekeurd worden"
- **Versturen** → `POST /quotes/:id/send` → **400** "Deze offerte vereist goedkeuring (bedrag boven de goedkeuringsgrens of sjabloon vereist het) en kan pas verstuurd worden nadat een bevoegde collega de offerte heeft goedgekeurd."

Er is **geen enkele knop** die de offerte naar `TER_GOEDKEURING` brengt. De gebruiker zit klem: beide
beschikbare acties geven een 400 en er is geen weg vooruit.

De backend werkt wél correct — `POST /api/v1/quotes/:id/submit-approval` geeft **201** en zet de status
op `TER_GOEDKEURING`; daarna werkt "Goedkeuren" en vervolgens "Versturen" gewoon in de UI
(geverifieerd: `CONCEPT → TER_GOEDKEURING → GOEDGEKEURD → VERSTUURD` op OFF-2026-0005).

## Reproductie
1. Login `manager@inspexi-demo.nl` (of `backoffice@…`).
2. Maak een offerte met een regel van € 25.000 excl. btw op het sjabloon "Standaard Inspectie Offerte".
3. Open de offerte → actiemenu: alleen **Goedkeuren**, **Versturen**, **Vraag goedkeuring aan team/persoon**.
4. Klik **Versturen** → 400 met de goedkeuringsmelding. Klik **Goedkeuren** → 400 statusmelding.
5. Er is geen "Ter goedkeuring"-actie.

## Bewijs
- HTTP: `POST /api/v1/quotes/8d7177d2-…/send` → **400** (goedkeuringsgate)
- HTTP: `POST /api/v1/quotes/8d7177d2-…/approve` → **400** (statusgate)
- HTTP: `POST /api/v1/quotes/8d7177d2-…/submit-approval` → **201** (werkt wél)
- Screenshot: `bevindingen/img/B-304-goedkeuring-deadend.png`
- Code: `apps/portal/src/pages/quotes/quote-detail-page.tsx` regel ~266:
  ```tsx
  ...(quote.status === QuoteStatus.CONCEPT && quote.requiresApproval ? [{ label: 'Ter goedkeuring', … }] : []),
  ...(quote.status === QuoteStatus.CONCEPT && !quote.requiresApproval ? [{ label: 'Goedkeuren', … }] : []),
  ```

## Analyse / vermoedelijke oorzaak
De UI kijkt alleen naar `quote.requiresApproval` (afkomstig van het **sjabloon**) en niet naar de
**org-drempel** (`Organization.quoteApprovalThreshold` + `quoteApprovalRequiredRole`). De backend
combineert beide triggers in `isQuoteApprovalRequired()` (`quotes.helpers.ts`), maar de frontend heeft
die tweede trigger niet. Voor offertes boven de drempel op een "gewoon" sjabloon valt de knop weg.

## Advies
- Lever de effectieve goedkeuringsplicht mee vanuit de API (bv. `approvalRequired: boolean` op de
  serialized quote) en laat de UI daarop sturen in plaats van op `requiresApproval` alleen.
- Toon dan **Ter goedkeuring** i.p.v. **Goedkeuren** en zet **Versturen** op disabled met een
  verklarende tooltip.

## Status
**Opgelost in WP-B5** (branch `fix/wp-b5-quote-chain`).
- De API serialiseert nu `approvalRequired` (org-drempel ÓF template-vlag, berekend met `isQuoteApprovalRequired()`) op de offerte-detailresponse — één bron van waarheid (`QuotesService.findOne`).
- De actiemenu-condities sturen op die effectieve vlag via `getQuoteApprovalState()` (`apps/portal/src/pages/quotes/components/quote-detail-helpers.ts`): boven de drempel verschijnt **Ter goedkeuring**; **Versturen** blijft disabled met verklarende tooltip tot er een goedgekeurd verplicht verzoek is.
- Aangrenzend meegenomen: de **Goedkeuren**-actie op een CONCEPT-offerte zónder goedkeuringsplicht riep `POST /approve` aan (altijd 400 — vereist TER_GOEDKEURING) en gebruikt nu de statusovergang `CONCEPT → GOEDGEKEURD`.
- Vitest-regressietest: drempel-actief → "Ter goedkeuring" zichtbaar (`quote-detail-helpers.test.ts`).
