# B-306 — Interne notities van een planregel staan letterlijk op de publieke (anonieme) afspraakpagina

- **Testgeval:** BO-40
- **Actor / rol:** Backoffice / MANAGER (schrijft de notitie) — lek richting anonieme bezoeker
- **App:** Portal (:5173) publieke route `/afspraak/:token` + API (:3001) `/public/planning/:token`
- **Severity:** S2 (ernstig — vertrouwelijke interne informatie naar buiten; geen auth nodig)
- **Type:** informatielek / verkeerde veldselectie
- **Datum/tijd:** 2026-07-27 11:22

## Verwacht
`PlanningItem.internalNotes` heet in de portal **"Interne notities"** en hoort alleen intern zichtbaar
te zijn. De publieke afspraakpagina toont datum, tijd, locatie, soort inspectie en (met consent) de
inspecteur — géén interne notities.

## Werkelijk
De publieke pagina rendert `internalNotes` onder het kopje **"Opmerkingen"**, zichtbaar voor iedereen
met de link (geen login, geen tenantcontrole nodig):

> **Opmerkingen**
> Hele werkdag; inspecteur staat op PENDING (nog niet geaccepteerd).

Ook de onderliggende publieke API geeft het veld ongefilterd terug:

```bash
curl -H "Host: inspexidemo.localhost" \
  http://localhost:3001/api/v1/public/planning/d97fc66b-8f4e-40d2-8dcb-ff75a6c7a434
# → 200
# "productName": "TP Planning — gepland 10 aug",
# "internalNotes": "Hele werkdag; inspecteur staat op PENDING (nog niet geaccepteerd)."
```

Extra pijnlijk: dezelfde service doet voor inspecteur-contactgegevens wél een expliciete "leak-strip"
(`toPublicInspectorUser`, consent-velden), maar het item zelf wordt met een spread ongefilterd
teruggegeven.

## Reproductie
1. Login als backoffice en zet op een planregel een interne notitie
   (Planning → planregel → Bewerken → "Interne notities").
2. Haal de `publicToken` van de planregel op (of gebruik "Klantportaal"-tab).
3. Open in een anonieme context `http://inspexidemo.localhost:5173/afspraak/<token>`.
4. De notitie staat onder "Opmerkingen".

## Bewijs
- HTTP: `GET /api/v1/public/planning/:token` → 200 met `internalNotes` in de payload (zonder auth).
- Screenshot: `bevindingen/img/B-306-interne-notitie-publiek.png`
- Code:
  - `apps/api/src/modules/planning/planning-public.service.ts` — `findByPublicToken()` includeert het
    volledige `item` en spreidt het uit; er is geen veldselectie/strip voor `internalNotes`.
  - `apps/portal/src/pages/planning/planning-public-page.tsx:529-532` —
    `{data.internalNotes && (<h2>Opmerkingen</h2><p>{data.internalNotes}</p>)}`

## Analyse / vermoedelijke oorzaak
Waarschijnlijk is "Opmerkingen" ooit bedoeld als klantgerichte toelichting, maar er is geen apart
`clientNotes`-veld; men heeft `internalNotes` hergebruikt. Het veld heet en gedraagt zich intern
(alleen zichtbaar voor staf in de detailpagina), dus gebruikers zullen er ongefilterd interne
informatie in zetten.

## Advies
- Verwijder `internalNotes` uit de publieke payload (expliciete `select` i.p.v. spread) én uit
  `planning-public-page.tsx`.
- Introduceer een apart, duidelijk gelabeld veld `clientNotes` / "Opmerking voor de klant" wanneer de
  functionaliteit gewenst is.
- Voeg een e2e-test toe die asserteert dat de publieke payload geen `internalNotes` bevat.

## Status

**Opgelost** (WP-B7, branch `fix/wp-b7-public-endpoints`, 2026-07-27).

- `planning-public.service.findByPublicToken()` gebruikt nu een **expliciete
  `select`-allowlist** (alleen wat de publieke afspraakpagina toont) in plaats van
  `include` + record-spread; `internalNotes` en alle andere interne kolommen
  (`orgId`, `createdBy`, `cancelReason`, `publicToken`, …) zitten niet meer in de
  publieke payload. `orgId` wordt alleen server-side gebruikt voor de
  inspecteur-contactresolutie en vóór de return gestript.
- `planning-public-page.tsx`: het "Opmerkingen"-blok (dat `internalNotes`
  rendeerde) is verwijderd.
- **Generieke bescherming:** key-snapshot-e2e (`test/public-endpoints.e2e-spec.ts`)
  asserteert de exacte set toplevel- en genestte sleutels van de publieke
  planning- én offerte-payload — elk nieuw veld vereist een bewuste toelating.
- Een apart klantgericht `clientNotes`-veld is **bewust niet** meegenomen
  (migratievrij gehouden); genoteerd als follow-up in de PR.
- **Privacy-nazorg:** bestaande interne notities stonden al publiek achter
  gedeelde tokens → advies: publicTokens van planregels roteren na uitrol.
