# B-307 — Aanvrager kan zijn eigen offerte boven de goedkeuringsdrempel zelf goedkeuren (geen vier-ogen)

- **Testgeval:** BO-25
- **Actor / rol:** Backoffice / MANAGER
- **App:** API (:3001) + Portal (:5173) · org: inspexidemo (drempel € 10.000, vereiste rol MANAGER)
- **Severity:** S2 (ernstig — de verplichte goedkeuringsgate is door één persoon te doorlopen)
- **Type:** autorisatie / procescyclus
- **Datum/tijd:** 2026-07-27 11:03

## Verwacht
De goedkeuringsgate bestaat om een tweede paar ogen af te dwingen op offertes boven de org-drempel.
Een gebruiker die het goedkeuringsverzoek indient, hoort dat verzoek **niet zelf** te mogen goedkeuren
(vergelijk het vier-ogen-principe dat voor inspectieplannen wél expliciet geïmplementeerd is).

## Werkelijk
Eén MANAGER kan de volledige keten alleen doorlopen:

```
POST /api/v1/quotes/17590675-…/submit-approval   (als manager@inspexi-demo.nl) → 201
POST /api/v1/quotes/17590675-…/approve           (als DEZELFDE manager)        → 201
```

Resultaat in de database:

| quote_number | ar.status | kind | requested_by | reviewed_by |
|---|---|---|---|---|
| OFF-2026-0006 | APPROVED | THRESHOLD | manager@inspexi-demo.nl | **manager@inspexi-demo.nl** |

De offerte staat daarna op `GOEDGEKEURD` en mag verstuurd worden — de drempel van € 10.000 is
effectief betekenisloos zodra de opsteller zelf MANAGER is.

**Wel goed:** de rolgate werkt. Een BACKOFFICE-gebruiker die probeert goed te keuren krijgt **403**.

## Reproductie
1. Login `manager@inspexi-demo.nl`.
2. Maak een offerte van € 25.000 excl. btw (totaal € 30.250) met een sjabloon.
3. `POST /api/v1/quotes/:id/submit-approval` (als deze manager) → 201, status `TER_GOEDKEURING`.
4. `POST /api/v1/quotes/:id/approve` (als dezelfde manager) → 201, status `GOEDGEKEURD`.
5. `POST /api/v1/quotes/:id/send` → 201, offerte gaat naar de klant.

## Bewijs
- HTTP-statussen zoals hierboven (`NODE_ENV=test`, host-header `inspexidemo.localhost`).
- DB:
  ```sql
  select ar.status, ru.email requested_by, rv.email reviewed_by
  from imp_quote_approval_requests ar
  join imp_users ru on ru.id = ar.requested_by
  left join imp_users rv on rv.id = ar.reviewed_by;
  -- APPROVED | manager@inspexi-demo.nl | manager@inspexi-demo.nl
  ```
- Console: n.v.t. (API-niveau).

## Analyse / vermoedelijke oorzaak
`QuoteApprovalsService.approve()` controleert alleen de **rol** (`@Roles`/`quoteApprovalRequiredRole`),
niet of `reviewedBy !== requestedBy`. Voor inspectieplannen bestaat de vier-ogen-gate wél
(`inspectionReviewEnabled`), maar voor offertes ontbreekt het equivalent. Dit sluit aan op het al
gesignaleerde openstaande punt "vier-ogen: reviewer ≠ author" uit de test-env-readiness review.

## Advies
- Weiger `approve()`/`reject()` wanneer `approvalRequest.requestedBy === user.id` (400/403 met NL-melding),
  ten minste voor `kind = THRESHOLD`.
- Maak dit configureerbaar per org als er kleine organisaties zijn waar dit niet haalbaar is, maar zet
  de default op "aan".
