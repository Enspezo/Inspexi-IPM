# B-309 — Staffelprijzen worden nooit toegepast: de offerte-editor stuurt geen `quantity` naar `resolve-price` en herberekent niet bij aantalwijziging

- **Testgeval:** BO-21
- **Actor / rol:** Backoffice / MANAGER
- **App:** Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — structureel verkeerde prijzen op klantoffertes)
- **Type:** logische fout / ontbrekende parameter
- **Datum/tijd:** 2026-07-27 11:09

## Verwacht
"Klantgroep-contact met staffelprijstabel → regel pakt staffelprijs | Juiste prijs uit tier."
Bij `TP Meetpunt (staffel)` voor `TP VIP Installaties BV` (klantgroep met `TP VIP-prijstabel`):

| aantal | verwachte stuksprijs |
|---|---|
| 1 – 9 | € 12,50 |
| 10 – 49 | € 10,00 |
| 50+ | € 7,50 |

## Werkelijk
De eenheidsprijs blijft **altijd € 12,50**, ongeacht het aantal. Gemeten in de editor:

| aantal ingevuld | eenheidsprijs in de UI | regeltotaal | correct zou zijn |
|---|---|---|---|
| 1 | 12,50 | € 12,50 | € 12,50 ✔ |
| 10 | 12,50 | € 125,00 | € 100,00 ✘ |
| 50 | 12,50 | € 625,00 | € 375,00 ✘ |
| 9 | 12,50 | € 112,50 | € 112,50 ✔ |

De **backend is correct**; het endpoint resolvet de tier prima zodra je `quantity` meegeeft:

```
GET /quotes/resolve-price?productId=…&contactId=…&quantity=1   → 12.5
GET /quotes/resolve-price?productId=…&contactId=…&quantity=10  → 10
GET /quotes/resolve-price?productId=…&contactId=…&quantity=50  → 7.5
GET /quotes/resolve-price?productId=…&contactId=…              → 12.5   ← zoals de portal aanroept
```

De portal laat `quantity` weg, dus `parseFloat(undefined) || 1` maakt er altijd 1 van → altijd de
laagste staffel. Bovendien wordt de prijs alleen opgehaald bij **"Product toevoegen"**; wijzigt de
gebruiker daarna het aantal, dan gebeurt er niets.

## Reproductie
1. Login `manager@inspexi-demo.nl`.
2. Nieuwe offerte voor **TP VIP Installaties BV** → **Bewerken**.
3. Kies product **TP Meetpunt (staffel)** → **Product toevoegen** (aantal 1, prijs € 12,50).
4. Zet aantal op **50**. De eenheidsprijs blijft € 12,50; regeltotaal € 625,00 i.p.v. € 375,00.
5. In Network is er slechts één `GET /api/v1/quotes/resolve-price?productId=…&contactId=…` — zonder
   `quantity`, en geen herberekening na de aantalwijziging.

## Bewijs
- HTTP-vergelijking hierboven (met/zonder `quantity`).
- Code `apps/portal/src/pages/quotes/quote-editor-page.tsx:191-195`:
  ```ts
  const qs = new URLSearchParams();
  qs.set('productId', pendingProductId);
  qs.set('contactId', selectedContactId);      // ← quantity ontbreekt
  const resolved = await apiClient.get<ResolvedPrice>(`/quotes/resolve-price?${qs.toString()}`);
  ```
  en er is geen effect/handler die `resolve-price` opnieuw aanroept bij `quantity`-wijziging.
- Backend `apps/api/src/modules/quotes/quotes.service.ts:527-553` (`resolvePrice`) — tier-lookup is correct.
- Console: geen fouten.

## Analyse / vermoedelijke oorzaak
De query-parameter is bij de implementatie van de editor vergeten; de controller vangt dat af met
`parseFloat(quantity) || 1`, waardoor het stilletjes "werkt" met tier 1. Hierdoor is de hele
TIERED-prijstabel functioneel dood in de portal.

## Advies
- Voeg `qs.set('quantity', String(quantity))` toe bij het toevoegen van een product.
- Herbereken (debounced) bij elke wijziging van `quantity` op een regel met `productId`, en toon
  duidelijk dat de prijs uit een staffel komt (bv. "staffel 10–49: € 10,00").
- Voeg een portal-unittest toe die de staffelovergang 9 → 10 controleert.

## Status
**Opgelost in WP-B5** (branch `fix/wp-b5-quote-chain`).
- De editor stuurt `quantity` nu expliciet mee naar `GET /quotes/resolve-price` (bij product-toevoegen én bij herberekening).
- Aantalwijziging op een productregel triggert een gedebouncede (400 ms) herberekening van de eenheidsprijs — met een `priceOverridden`-vlag: zodra de gebruiker de prijs handmatig aanpast, wordt die nooit meer overschreven door de resolver.
- Herkomst zichtbaar onder het prijsveld: "staffel 10–49: € 10,00" / "vaste prijs: € 85,00" — de API geeft daarvoor `priceType` + `tier` terug in de resolve-price-response.
- Tier-grenstests: unit op 9→10 en 49→50 (`quotes.service.spec.ts`) + e2e op de geseede staffel (5→6 en 10→11).
