# B-310 — Meerdaagse planning: sessies zijn via de portal niet aan een inspecteur toe te wijzen, waardoor "Bevestigen" nooit verschijnt

- **Testgeval:** BO-40
- **Actor / rol:** Backoffice / MANAGER
- **App:** Portal (:5173) · org: inspexidemo
- **Severity:** S2 (ernstig — meerdaagse planning kan via de UI niet worden afgerond)
- **Type:** ontbrekende UI-actie
- **Datum/tijd:** 2026-07-27 11:18

## Verwacht
BO-40: "Confirm sessie → bevestiging naar klant → publieke `/afspraak/:token` accepteren |
Sessie DEFINITIEF". Op de tab **Sessies** van een meerdaagse planregel moet je per sessie een datum
kunnen zetten, een inspecteur kunnen toewijzen en de sessie definitief kunnen maken.

## Werkelijk
De sessietab biedt per sessie alleen: **Datum instellen / Wijzigen**, **Notitie toevoegen**,
**Verzetten** en **Annuleren**. Er is **geen actie om een inspecteur aan een sessie toe te wijzen**.
De knop **Bevestigen** verschijnt alleen bij `session.status === CONCEPT`, en een sessie komt pas op
CONCEPT nádat er een inspecteur aan gekoppeld is. Resultaat: een meerdaagse planregel blijft via de UI
eeuwig op `NOG_TE_PLANNEN` en kan nooit definitief worden.

De API kán het wel:

```
POST /api/v1/planning/:id/sessions/:sessionId/assign  {"inspectorIds":["…"]} → 200
→ sessie gaat naar CONCEPT, waarna "Bevestigen" in de UI verschijnt en de sessie DEFINITIEF wordt.
```

Na die API-omweg werkte de rest van BO-40 wel: sessie 1 → **Definitief**, planregel-badge
"Meerdaags · 1/2 definitief", publieke `/afspraak/:token` toont de sessies, `.ics` werkt
(`GET /public/planning/:token/ics` → 200, geldige VCALENDAR) en `POST …/send-confirmation` → 200.

## Reproductie
1. Login `manager@inspexi-demo.nl`.
2. Maak een meerdaagse planregel (`isMultiDay: true`, `sessionCount: 2`) — of open
   "TP Planning — meerdaags (2 sessies)".
3. Tab **Sessies (0/2 definitief)** → **Datum instellen** op sessie 1 → **Opslaan**.
4. Er is geen knop om een inspecteur te koppelen; **Bevestigen** ontbreekt.
5. `Array.from(document.querySelectorAll('main button')).map(b=>b.innerText)` levert:
   `Datum instellen | Verzetten | Annuleren | … | + Sessie toevoegen` — geen assign/bevestigen.

## Bewijs
- Code `apps/portal/src/pages/planning/components/planning-sessions-tab.tsx`:
  - regel ~265-286: sessie-inspecteurs worden alleen **getoond** (avatars + acceptatiestatus).
  - regel ~301: `{userCanWrite && session.status === SessionStatus.CONCEPT && <Button …>Bevestigen</Button>}`
  - `grep -n "assign" planning-sessions-tab.tsx` → **geen treffers**; de portal roept
    `POST …/sessions/:sessionId/assign` nergens aan.
- HTTP: `POST /api/v1/planning/130e5cb8-…/sessions/79a79ee2-…/assign` → **200**, sessie → `CONCEPT`.
- DB na bevestigen: `imp_planning_sessions.status = DEFINITIEF`, `is_definitief = t`.

## Analyse / vermoedelijke oorzaak
De sessie-toewijzingsflow is backend-side compleet (assign/accept/reject/confirm/reschedule/complete)
maar de bijbehorende UI-actie is nooit gebouwd; de sessietab is read-only op het punt van inspecteurs.

## Advies
- Voeg per sessie een **"Inspecteurs toewijzen"**-knop toe die dezelfde modal gebruikt als de
  planregel (inclusief de beschikbaarheidscheck + 409/override-dialoog).
- Toon **Bevestigen** ook bij `NOG_TE_PLANNEN` zodra er een datum staat, of maak duidelijk zichtbaar
  waarom de knop ontbreekt.

## Status
**Opgelost** — WP-B8, branch `fix/wp-b8-session-assign` (PR naar `dev`:
"fix(portal): assign inspectors to planning sessions from sessions tab (WP-B8)").

- Root cause bevestigd: `planning-sessions-tab.tsx` riep
  `POST /planning/:id/sessions/:sessionId/assign` nergens aan (de hook
  `useAssignSessionInspectors` bestond al maar had nul gebruikers), en "Bevestigen"
  verscheen alleen bij `CONCEPT` — een status die zonder assign onbereikbaar is.
- Fix: per sessie (bij `NOG_TE_PLANNEN`/`CONCEPT`) een knop **"Inspecteurs toewijzen"** die de
  **bestaande** `InspectorAssignModal` van de planregel hergebruikt via een nieuwe optionele
  `sessionId`-prop — inclusief de "Niet beschikbaar"-badges op de sessiedatum en de
  409+`warnings`-override-dialoog (`useAvailabilityOverride`). De sessie-variant deelt exact
  dezelfde payload (`inspectorIds`, `primaryInspectorId`, `overrideAvailabilityWarnings`).
- Dead-end structureel weg: bij `NOG_TE_PLANNEN` staat "Bevestigen" nu zichtbaar maar disabled,
  met een tooltip die uitlegt wat er ontbreekt ("Wijs eerst een inspecteur toe …" /
  "Stel eerst een datum in …" / beide).
- `useAssignSessionInspectors` invalideert nu ook de planning-lijstquery (de backend upsert
  bij sessie-assign ook `PlanningInspector`-rijen op de parent-planregel).
- Regressietests (Vitest): `planning-sessions-tab.test.tsx` — toewijzen-actie zichtbaar,
  modal-flow met payload, query-invalidatie via de echte hook, 409→override-dialoog→override-call,
  disabled-Bevestigen-tooltips en actieve Bevestigen bij `CONCEPT`.
