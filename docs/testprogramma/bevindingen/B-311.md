# B-311 — Elk gegenereerd PDF-document toont de onopgeloste placeholder `{{organization.name}}` in de paginakop

- **Testgeval:** BO-47, BO-48, BO-50
- **Actor / rol:** Backoffice / MANAGER
- **App:** API (:3001) documentgeneratie (Puppeteer) · org: inspexidemo
- **Severity:** S3 (matig — cosmetisch/onprofessioneel op een klantgericht document)
- **Type:** template-/rendering-fout
- **Datum/tijd:** 2026-07-27 11:37

## Verwacht
De koptekst van het documentsjabloon (`<div>{{organization.name}} — Inspectieplan</div>`) hoort
gerenderd te worden als **"InspeXi Demo — Inspectieplan"**.

## Werkelijk
Boven aan elke pagina van elk gegenereerd PDF staat letterlijk:

```
{{organization.name}} — Inspectieplan
```

De **body** van het document is wél correct gevuld (projectgegevens, opdrachtgever, bevindingen), en de
footer klopt ook (`Pagina 1 van 1`) omdat `pageNumber`/`totalPages` wél vervangen worden.

## Reproductie
1. Login `manager@inspexi-demo.nl`.
2. Open een inspectieplan met een gekoppelde inspectie-template (bv. via
   `POST /api/v1/inspection-plans` met `inspectionTemplateId`).
3. Tab **Documenten** → **Inspectieplan genereren**.
4. Download de PDF (`GET /api/v1/generated-documents/:id/download?format=pdf`).
5. De kop van pagina 1 toont `{{organization.name}} — Inspectieplan`.

## Analyse / vermoedelijke oorzaak
`formatHeaderFooter()` vertaalt alleen de vijf ingebouwde Puppeteer-tokens. Data-placeholders zoals
`{{organization.name}}` (en elke andere `{{…}}` uit het templatemodel) worden niet door de
Handlebars-/variabelenlaag gehaald voordat ze als `headerTemplate` aan Puppeteer worden gegeven.

## Advies
- Render header- en footer-HTML door dezelfde variabelenresolver als de body, vóór de aanroep van
  `formatHeaderFooter()`.
- Voeg een fallback toe die overgebleven `{{…}}`-tokens verwijdert i.p.v. ze te tonen, en log ze als
  waarschuwing.

## Status
**Opgelost** (WP-C4, branch `fix/wp-c4-docgen-overflow`, 2026-07-27).

- `formatHeaderFooter()` (`pdf-generation.service.ts`) zet nu éérst de vijf Puppeteer-tokens om
  naar hun `<span>`-vorm en haalt daarna de header/footer door **dezelfde Handlebars-resolver als
  de body** (gedeelde instance uit `handlebars-setup.ts`, incl. helpers). De benodigde data komt
  als `PdfOptions.headerFooterContext` mee.
- `GeneratedDocumentsService.pdfOptionsFor()` bouwt daarvoor bij preview/export/download een
  **lichte header-context** (`GenerationContextService.buildHeaderContextForPlan`) — alléén als de
  header/footer daadwerkelijk data-placeholders bevatten. Werkt dus ook direct voor **bestaande**
  documenten (header komt uit de template, niet uit de opgeslagen HTML).
- **Vangnet**: resterende `{{…}}`-tokens (onbekend, plan verdwenen, of niet-parsebaar) worden
  gestript i.p.v. getoond, met een `logger.warn` mét template-id.
- Geverifieerd met vóór/ná-preview-PDF's van het demo-plan-document: kop toont nu
  **"InspeXi Demo — Inspectieplan"**; footer (`Pagina 1 van 1`) blijft werken. Unit tests dekken
  tokens → spans, resolutie, HTML-escaping, en het strip-vangnet (incl. warn + template-id).
