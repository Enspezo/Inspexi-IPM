# B-313 — `PATCH /inspection-plans/:id` negeert `inspectionTemplateId` stilzwijgend (200 OK, geen effect)

- **Testgeval:** BO-47 (opzet documentgeneratie)
- **Actor / rol:** Backoffice / MANAGER
- **App:** API (:3001) · org: inspexidemo
- **Severity:** S3 (matig — stille no-op op een gedocumenteerd veld; gebruiker denkt dat het gelukt is)
- **Type:** logische fout (ontbrekende veldmapping)
- **Datum/tijd:** 2026-07-27 11:33

## Verwacht
`inspectionTemplateId` staat in `CreateInspectionPlanDto` en `UpdateInspectionPlanDto` erft daarvan via
`PartialType`. Een PATCH met dat veld hoort de template te koppelen — of, als koppelen na aanmaken niet
mag, een 400 met uitleg te geven.

## Werkelijk
De PATCH slaagt met **200 OK** en de response bevat het plan, maar `inspection_template_id` blijft
**NULL**. Er is geen melding, geen waarschuwing, niets.

```bash
PATCH /api/v1/inspection-plans/16a193cd-…  {"inspectionTemplateId":"85690766-…"}   → 200
SELECT reference_number, inspection_template_id FROM imp_inspection_plans …
-- BO-RAP-041 | (leeg)
```

Gevolg in de praktijk: een plan dat zonder template is aangemaakt kan nooit meer een template krijgen,
en documentgeneratie blijft daarop stuiten met **"Plan heeft geen inspectie-template"** (400) —
zonder dat duidelijk is hoe je dat oplost. Alle TP-plannen in de seed hebben dit probleem.

## Reproductie
1. `POST /api/v1/inspection-plans` **zonder** `inspectionTemplateId` → 201.
2. `PATCH /api/v1/inspection-plans/:id` met `{"inspectionTemplateId":"<geldig id>"}` → **200**.
3. `GET /api/v1/inspection-plans/:id` → `inspectionTemplateId: null`.
4. Documenten-tab → **Rapport genereren** → toast "Plan heeft geen inspectie-template".

## Bewijs
- HTTP: PATCH → 200; DB-veld blijft NULL (query hierboven).
- Code `apps/api/src/modules/inspection-plans/inspection-plans.service.ts`, `update()`:
  - regel ~352: `this.assertTemplateUsable(dto.inspectionTemplateId, orgId)` — het veld wordt **wel**
    gevalideerd,
  - maar in het `data`-object (regels ~357-…) wordt `inspectionTemplateId` **nergens** gemapt
    (`grep -n "inspectionTemplate"` over de hele `update()` geeft alleen de validatieregel).

## Analyse / vermoedelijke oorzaak
Bij het overzetten naar de expliciete PATCH-mapping ("map alleen aanwezige velden") is deze ene
toewijzing vergeten; de validatie is blijven staan, waardoor het lijkt alsof het veld ondersteund wordt.

## Advies
- Voeg toe: `if (dto.inspectionTemplateId !== undefined) data.inspectionTemplate = dto.inspectionTemplateId ? { connect: { id: dto.inspectionTemplateId } } : { disconnect: true };`
- Of, als de koppeling bewust immutable is: verwijder het veld uit de update-DTO zodat een PATCH een
  duidelijke 400 geeft.
- Overweeg een generieke test die elk DTO-veld tegen de servicemapping controleert; dit type stille
  no-op is anders lastig te vinden.

## Status

**Opgelost in WP-C5** (branch `fix/wp-c5-config-validation`):
- `update()` mapt `inspectionTemplateId` nu wél: connect bij een id, disconnect bij `null`.
  **Bewuste keuze:** koppelen/wisselen mag in élke status — consistent met
  contactId/locationId/normTypeCode die hier ook onbeperkt muteerbaar zijn, en het is juist
  het herstelpad voor plannen die zonder template zijn aangemaakt (documentgeneratie
  blokkeerde anders permanent). Beperken tot `draft` zou precies die reparatie onmogelijk maken.
- De **generieke DTO↔mapping-regressietest** uit het advies is toegevoegd
  (inspection-plans.service.spec): elk veld van `UpdateInspectionPlanDto` moet in de
  Prisma-write belanden of expliciet in een uitsluitlijst staan. Die test onthulde direct
  dezelfde stille no-op op **addressStreet/addressHouseNumber/addressPostalCode/addressCity/
  gpsLatitude/gpsLongitude/installationResponsibleId** — allemaal in dezelfde fix gemapt.
- **Seed gefixt**: alle TP-plannen (incl. het testbedrijf-plan) krijgen in
  `prisma/seed-tp/inspectie.ts` het systeem-template `IT-NEN1010-INITIAL` (lookup met
  nette waarschuwing als het ontbreekt), zodat documentgeneratie op de TP-plannen werkt.
- Tests: 3 unit (connect/disconnect/generieke mapping) + 1 e2e (PATCH → GET toont template).
