# B-314 — "Notitie bij afwijzing (optioneel)" is in werkelijkheid verplicht; de gebruiker krijgt de rauwe Engelse melding "note must be a string"

- **Testgeval:** BO-25
- **Actor / rol:** Backoffice / MANAGER
- **App:** Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S3 (matig — misleidend label + niet-Nederlandse, technische foutmelding)
- **Type:** contract-mismatch frontend/backend
- **Datum/tijd:** 2026-07-27 11:06

## Verwacht
Of het veld is echt optioneel (afwijzen zonder notitie lukt), of het is verplicht en dan hoort het
label dat te zeggen én hoort de melding Nederlands en bij het veld te staan
("Geef een reden voor de afwijzing").

## Werkelijk
Op een offerte in `TER_GOEDKEURING` toont **Afwijzen** een invoerveld met placeholder
**"Notitie bij afwijzing (optioneel)…"**. Laat je het leeg en klik je op **Bevestig afwijzing**, dan
verschijnt de rode toast:

```
note must be a string
```

De offerte blijft op `TER_GOEDKEURING` staan (data ongewijzigd — goed), maar de gebruiker krijgt geen
bruikbare uitleg. Mét notitie werkt het correct: status → `CONCEPT`, approval-request → `REJECTED`
met de notitie, en notificatie `OFFERTE_AFGEWEZEN` naar de aanvrager.

## Reproductie
1. Login `manager@inspexi-demo.nl`, open `TP-OFF-002` (status Ter goedkeuring).
2. Klik **Afwijzen** → er verschijnt "Notitie bij afwijzing (optioneel)…".
3. Klik **Bevestig afwijzing** zonder iets in te vullen.
4. Toast: `note must be a string`.

## Bewijs
- HTTP: `POST /api/v1/quotes/e5cd907b-…/reject` met `{}` → **400** `note must be a string`
- Backend DTO `apps/api/src/modules/quotes/dto/review-approval.dto.ts`:
  ```ts
  export class RejectQuoteDto {
    @ApiProperty({ description: 'Verplichte reden voor afwijzing' })
    @IsString()          // ← géén @IsOptional
    note: string;
  }
  ```
- Frontend `apps/portal/src/pages/quotes/hooks/use-quotes.ts:165-167`:
  ```ts
  interface RejectQuoteDto { note?: string; }   // ← optioneel getypt
  ```
- Console: geen JS-fouten.

## Analyse / vermoedelijke oorzaak
Het portal-type en het UI-label zijn "optioneel", de backend-DTO is verplicht. De class-validator-melding
wordt ongewijzigd als toast getoond (zie ook B-106/B-155 over Engelse API-meldingen).

## Advies
- Maak het veld in de UI verplicht (label zonder "(optioneel)", knop disabled zolang leeg) met een
  Nederlandse zod-melding, en pas het frontend-type aan naar `note: string`.
- Voeg een NL-`message` toe aan de `@IsString()` in `RejectQuoteDto` als vangnet.
