# B-402 — Berichten van de klant komen nergens aan: geen staf-endpoint, geen staf-UI, geen notificatie

- **Testgeval:** KL-15
- **Actor / rol:** Klant (ClientUser) → staf (MANAGER/BACKOFFICE)
- **App:** Client-portal (:5174) + Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S2 (ernstig — gouden pad breekt; de klant krijgt een valse bevestiging)
- **Type:** onvolledige functionaliteit / dead-end
- **Datum/tijd:** 2026-07-27 10:19

## Verwacht
KL-15: "Bericht sturen in Berichten-tab + bijlage → verschijnt; **staf ontvangt**; ongelezen-teller
klopt." De klant stelt een vraag bij een inspectie, de organisatie ziet die en kan antwoorden.

## Werkelijk
Het bericht wordt correct opgeslagen en getoond in het klantportaal, maar:

1. Er is **geen enkel staf-endpoint** dat `InspectionMessage` uitleest. In de hele API komt het
   model alleen voor in `client-messages.service.ts` (en in de seed-cleanup).
2. Er is **geen staf-UI**: in `apps/portal/src` bestaat geen enkele referentie naar berichten van
   een inspectie.
3. Er wordt **geen notificatie** gedispatcht — `imp_notifications` blijft ongewijzigd na het
   versturen (laatste rij bleef `INSPECTIEPLAN_AFGEKEURD` van 09:32).
4. De **bijlage** uit het testgeval bestaat niet: `SendMessageDto` heeft alleen `content`, en er is
   geen upload-endpoint — terwijl het model `MessageAttachment` wél in het schema staat.

De klant ziet zijn bericht keurig in de tijdlijn staan en gaat er dus van uit dat de vraag gesteld
is. Er is niemand die 'm ooit ziet.

## Reproductie
1. Login klantportaal (`tp-signer@klant.nl` / `Password123!`) op `inspexidemo.localhost:5174`.
2. Open `/inspections/ce42f284-80a6-4b1c-8e07-fbc5cedd3cc2` → tab **Berichten**.
3. Typ een bericht → **Verstuur**. Het bericht verschijnt rechts in de tijdlijn.
4. Verifieer in de DB:
   ```sql
   select id, left(content,60), created_at from imp_inspection_messages order by created_at desc limit 1;
   -- 6646bbc5-… | Vraag van klant <script>alert('kl15')</script> & 'quote' 🚀 测 | 2026-07-27 10:19:41
   select type, title, created_at from imp_notifications order by created_at desc limit 1;
   -- INSPECTIEPLAN_AFGEKEURD | … | 2026-07-27 09:32:00   ← geen nieuwe notificatie
   ```
5. Zoek een staf-route: `GET /api/v1/inspection-plans/{planId}/messages` → **404 "Cannot GET …"**.

## Bewijs
- HTTP: `POST /api/v1/client/inspections/{id}/messages` → 201 (opslaan werkt).
- HTTP: `GET /api/v1/inspection-plans/{id}/messages` → 404 (route bestaat niet).
- Code: `grep -rn "inspectionMessage" apps/api/src apps/portal/src` → uitsluitend
  `apps/api/src/modules/client-messages/client-messages.service.ts`.
- Positief punt: de injectiestring wordt netjes als tekst getoond (geen XSS).

## Analyse / vermoedelijke oorzaak
De klantzijde van het berichtenkanaal (module `client-messages`, met `list`, `send` en
`markRead` voor **staf**-berichten) is geïmplementeerd; de stafzijde (schrijven + lezen + notificatie)
is nooit gebouwd. `InspectionMessage.userId` en `MessageAttachment` staan al klaar in het schema,
wat bevestigt dat dit als tweerichtingsverkeer bedoeld was.

## Advies
1. Bouw de staf-tegenhanger: `GET/POST /inspection-plans/:id/messages` (rol-gescoped) + een
   Berichten-tab op de staf-inspectiedetailpagina.
2. Dispatch bij een klantbericht een notificatie naar de PM/reviewer/toegewezen inspecteur (analoog
   aan `HERSTEL_*` in `client-repair`), inclusief e-mail.
3. Zolang 1+2 niet bestaan: verberg de Berichten-tab in het klantportaal, of vervang de bevestiging
   door een tekst die niet suggereert dat er iemand meeleest.
4. Implementeer de bijlage of verwijder `MessageAttachment` uit het schema.
