# B-408 — Publieke document-ondertekening legt geen IP-adres vast (onvolledige audit trail)

- **Testgeval:** PUB-05
- **Actor / rol:** Anonieme ondertekenaar via e-maillink `/sign/:requestId`
- **App:** Portal (:5173) + API (:3001) · org: inspexidemo
- **Severity:** S3 (matig — bewijskracht van de handtekening, geen functioneel defect)
- **Type:** ontbrekende audit-vastlegging / inconsistentie tussen kanalen
- **Datum/tijd:** 2026-07-27 10:35

## Verwacht
De kolom `imp_document_signatures.signed_ip_address` bestaat en wordt door de andere ondertekenpaden
gevuld. Bij de publieke offerte staat het bovendien letterlijk in de UI:
> "Door te ondertekenen gaat u akkoord met de offerte. **Uw IP-adres en tijdstip worden vastgelegd
> als audit trail.**"

Voor een rechtsgeldige handtekening op een inspectierapport is dezelfde vastlegging te verwachten.

## Werkelijk
Ondertekenen via de publieke link `/sign/:requestId` schrijft **geen** IP weg:

```sql
select signer_role, status, signer_name, signed_at, signed_ip_address
from imp_document_signatures where id='6ff35c85-…';
-- CLIENT | SIGNED | TP Signer Klant | 2026-07-27 10:35:40 | (leeg)
```

Ter vergelijking, dezelfde handtekening gezet via het **klantportaal** en via de **herstelsessie**:

```
CLIENT     | SIGNED | Sander Klant       | 2026-07-27 10:15:03 | ::1
HERSTELLER | SIGNED | Karel Kortsluiting | 2026-07-27 10:50:50 | ::1
```

## Reproductie
1. Zorg voor een `DocumentSignature` met status `REQUESTED` en een UUID in `signature_request_id`.
2. Open anoniem `http://inspexidemo.localhost:5173/sign/<requestId>`.
3. Naam invullen, handtekening tekenen, opslaan, **Document ondertekenen** → "Bedankt — document
   ondertekend".
4. Controleer `signed_ip_address` in `imp_document_signatures` → leeg.

## Bewijs
- Code `apps/api/src/modules/generated-documents/generated-documents.controller.ts:196-201`:
  ```ts
  @Post(':requestId/sign')
  @Public()
  async sign(@Param('requestId', ParseUUIDPipe) requestId: string, @Body() dto: PublicSignDto) {
    await this.signing.signViaRequest(requestId, dto);   // ← geen @Req()/ip meegegeven
  ```
- Code `document-signing.service.ts:178-186` — de `update` zet `signatureImage`, `signerName`,
  `signedAt`, `status`; `signedIpAddress` ontbreekt.
- Ter contrast `client-documents.service.ts` (`sign(..., ip?)`) en `client-repair.service.ts:945`,
  die het IP wél doorgeven.

## Analyse / vermoedelijke oorzaak
De publieke variant is later toegevoegd en heeft de `ip`-parameter niet overgenomen. Juist het
publieke kanaal is het kanaal waar de identiteit van de ondertekenaar het zwakst is (alleen een
e-maillink), dus dáár weegt de vastlegging het zwaarst.

## Advies
1. Geef in `SignatureRequestsController.sign` `@Req() req` mee en reik
   `req.ip ?? req.socket.remoteAddress` door aan `signViaRequest`, die het wegschrijft in
   `signedIpAddress` (identiek aan `client-documents.service.ts`).
2. Overweeg ook `user-agent` vast te leggen (de offerte-flow doet dat al via `clientUserAgent`).
3. Neem de audit-trail-mededeling ("uw IP en tijdstip worden vastgelegd") ook op op de
   `/sign`-pagina, zodat wat je belooft ook klopt met wat je doet.
