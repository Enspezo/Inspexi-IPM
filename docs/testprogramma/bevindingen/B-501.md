# B-501 — Grens- en validatiemeldingen in org-onboarding en -instellingen zijn Engels (zowel frontend-zod als backend-DTO)

- **Testgeval:** SU-07 (primair) · ook SU-05, OA-05, OA-06, OA-16
- **Actor / rol:** Superuser / SUPERUSER en Org-admin / ORG_ADMIN
- **App:** Portal (:5173) + API (:3001)
- **Severity:** S3 (matig — orakel §3 eist een NL-melding bij het juiste veld; hier staat de melding wél bij het veld, maar in het Engels)
- **Type:** validatie / taal & consistentie
- **Datum/tijd:** 2026-07-27 12:40

## Verwacht
`00-master-testplan.md` §3: "Foutmelding is **in het Nederlands**, begrijpelijk, en bij het juiste veld."
`CLAUDE.md`: "UI labels, **validatiemeldingen** … : Nederlands." De organisatie-onboarding doet dat op
de meeste velden ook keurig ("Naam moet minimaal 2 tekens bevatten", "Slug mag alleen kleine letters en
cijfers bevatten", "Slug is al in gebruik", "Ongeldige URL").

## Werkelijk
Op de numerieke grenzen valt de zod-/class-validator-default door, in een verder volledig Nederlands
formulier. Frontend en backend hanteren dezelfde grenzen (dus functioneel correct), maar beide melden
in het Engels.

**Frontend (formulier "Organisatie aanmaken", direct zichtbaar onder het veld):**

| Invoer | Melding |
|---|---|
| Standaard BTW = `-5` | `Number must be greater than or equal to 0` |
| Standaard BTW = `150` | `Number must be less than or equal to 100` |
| Standaard geldigheid = `0` | `Number must be greater than or equal to 1` |

**Backend (`POST/PATCH /organizations`, komt als toast in beeld):**

| Invoer | HTTP | Melding |
|---|---|---|
| `defaultVat: -5` | 400 | `defaultVat must not be less than 0` |
| `defaultVat: 150` | 400 | `defaultVat must not be greater than 100` |
| `defaultValidityDays: 0` | 400 | `defaultValidityDays must not be less than 1` |
| `name: "X"` | 400 | `name must be longer than or equal to 2 characters` |
| `quoteApprovalThreshold: -100` | 400 | `quoteApprovalThreshold must not be less than 0` |
| `aiReviewInstructions` (2001 tekens) | 400 | `aiReviewInstructions must be shorter than or equal to 2000 characters` |
| `roles: []` (PATCH `/users/:id/role`) | 400 | `roles must contain at least 1 elements` |
| `email: "geen-email"` (invite) | 400 | `email must be an email` |

Ter contrast: de business-meldingen in dezelfde flows zijn wél Nederlands
("Alleen een superuser kan de superuser rol toewijzen", "Er bestaat al een gebruiker met dit
e-mailadres", "Uitnodiging is verlopen").

## Reproductie
1. `http://mijn.localhost:5173/organizations` → **Nieuwe organisatie**.
2. Naam "Nieuwe Klant BV", slug `su07test`, **Standaard BTW = -5**, **Standaard geldigheid = 0** → Aanmaken.
3. Herhaal met BTW `150`.
4. Backend-variant:
```bash
TOK=<superuser accessToken>
curl -s -X POST -H 'Host: mijn.localhost' -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' \
  -d '{"name":"SU07 vat neg","slug":"su07vatneg","defaultVat":-5}' \
  http://localhost:3001/api/v1/organizations
```

## Bewijs
```
# frontend (zod, onder het veld, rood)
Number must be greater than or equal to 0
Number must be less than or equal to 100
Number must be greater than or equal to 1

# backend
HTTP 400 {"success":false,"message":"defaultVat must not be less than 0","statusCode":400}
HTTP 400 {"success":false,"message":"defaultValidityDays must not be less than 1","statusCode":400}
```
Geen 500, geen witte pagina; de grenzen zelf worden aan beide kanten correct afgedwongen en er wordt
niets opgeslagen.

## Analyse / vermoedelijke oorzaak
- Frontend: `z.number().min(0).max(100)` zonder `{ message: … }`.
- Backend: `@Min()/@Max()/@MinLength()/@MaxLength()/@ArrayMinSize()/@IsEmail()` zonder `message`-optie;
  er is geen globale NL-vertaallaag op de `ValidationPipe`.

## Verwant
- **B-155** — Engelse auth-/UUID-meldingen in de API (`Unauthorized`, `Validation failed (uuid is expected)`).
- **B-106** — Engelse RolesGuard-403's ("Forbidden resource").
- **B-302** — Engelse native browservalidatie op offerteregels.
Deze bevinding voegt de **DTO-/zod-grenswaardemeldingen in de organisatie- en gebruikersflows** toe.

## Advies
Geef elke `@Min/@Max/@MinLength/@MaxLength/@ArrayMinSize/@IsEmail` een NL `message`, of registreer een
`exceptionFactory` op de globale `ValidationPipe` die de class-validator-constraints naar Nederlandse
teksten vertaalt. Doe hetzelfde voor de zod-schema's in de portal.
