# B-504 — Een nieuw aangemaakte organisatie kan geen eerste gebruiker krijgen: onboarding loopt dood

- **Testgeval:** SU-01 → SU-10/SU-11 (onboarding-keten)
- **Actor / rol:** Superuser / SUPERUSER
- **App:** Portal (:5173) + API (:3001)
- **Severity:** S2 (ernstig — gouden pad R10 "onboarding" breekt na stap 1)
- **Type:** procesflow / autorisatie
- **Datum/tijd:** 2026-07-27 13:15

## Verwacht
Na SU-01 ("Organisatie aanmaken") moet de nieuwe organisatie in gebruik genomen kunnen worden: de
SUPERUSER kent een abonnement toe (SU-10) en er komt een eerste ORG_ADMIN in, waarna SU-11
("log in als die org-admin") uitvoerbaar is. Ergens in het product moet dus een pad bestaan om de
eerste gebruiker van een verse organisatie aan te maken.

## Werkelijk
Dat pad bestaat niet.

1. **Org-detailpagina (superuser-domein):** de tab **Gebruikers (0)** toont alleen
   "Geen gebruikers in deze organisatie" — er is geen enkele knop om iemand toe te voegen of uit te
   nodigen. De tab **Instellingen** bevat alleen naam/kleur/BTW/geldigheid/chat.
2. **Org-subdomein:** daar staat wél een knop **Uitnodigen**, maar die faalt altijd met
   **"Organisatie is vereist voor uitnodigingen"** (HTTP 400) — ook al staat de SUPERUSER op het
   subdomein van precies die organisatie.
3. Er is **geen** alternatief endpoint: `users.controller.ts` kent alleen `POST /users/invite`
   (ORG_ADMINS) en `POST /users/accept-invitation`; een directe "gebruiker aanmaken" bestaat niet.

Het netto-effect: een organisatie die via de UI wordt aangemaakt is onbruikbaar totdat iemand
handmatig een user + invitation in de database zet.

## Reproductie
1. Log in als `superuser@inspexi.nl` op `http://mijn.localhost:5173`.
2. **Organisaties → Nieuwe organisatie** → naam "Nieuwe Klant BV", slug `nieuweklant` → Aanmaken.
3. Open de organisatie → tab **Gebruikers (0)**: geen actieknop.
4. Ga naar `http://nieuweklant.localhost:5173`, log in als superuser, **Organisatie → Gebruikers →
   Uitnodigen**, vul `admin@nieuweklant.nl` + rol Org Admin in → Uitnodigen.

## Bewijs
UI-toast (waargenomen via MutationObserver): `"Organisatie is vereist voor uitnodigingen"`

```bash
TOK=<superuser accessToken>
curl -s -X POST -H 'Host: nieuweklant.localhost' -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@nieuweklant.nl","role":"ORG_ADMIN"}' \
  http://localhost:3001/api/v1/users/invite
# HTTP 400 {"success":false,"message":"Organisatie is vereist voor uitnodigingen","statusCode":400}
```

## Analyse / vermoedelijke oorzaak
`users.controller.ts`:

```ts
async invite(@Body() dto: InviteUserDto, @CurrentUser() user: User) {
  const invitation = await this.usersService.invite(user.orgId, dto, user);
```

De controller geeft `user.orgId` door — voor een SUPERUSER `null` — en `UsersService.invite()` gooit
dan `BadRequestException('Organisatie is vereist voor uitnodigingen')`. De tenantcontext van het
subdomein (`req.tenant.orgId`) wordt niet gebruikt. Zelfde patroon als B-502/B-503.

## Impact op dit testprogramma
SU-10 en SU-11 konden niet op de zelf aangemaakte org `nieuweklant` worden uitgevoerd; de
feature-gating is daarom geverifieerd op de geseede varianten `inspexicompleet` (plan Compleet) en
`inspexibasis` (plan Basis). Deze afwijking is als zodanig in het logboek genoteerd.

## Advies
Geef de SUPERUSER één van beide paden:
- laat `invite()` terugvallen op `tenant.orgId` (of accepteer een expliciete `orgId` in de DTO wanneer
  de aanroeper SUPERUSER is), en/of
- voeg op de org-detailpagina onder **Gebruikers** een knop "Eerste beheerder uitnodigen" toe die
  `POST /organizations/:id/invite` aanroept.
