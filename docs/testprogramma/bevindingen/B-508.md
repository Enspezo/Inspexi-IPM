# B-508 — Elk tabblad van Organisatie-instellingen slaat de héle organisatie op; een lege goedkeuringsdrempel wordt stil `0`

- **Testgeval:** OA-05 (waargenomen tijdens OA-01/OA-07)
- **Actor / rol:** Org-admin / ORG_ADMIN
- **App:** Portal (:5173) · org: inspexidemo
- **Severity:** S2 (ernstig — stille wijziging van een businessregel die de gebruiker niet aanraakte)
- **Type:** grenswaarde / statusflow
- **Datum/tijd:** 2026-07-27 14:15

## Verwacht
OA-05: "`quoteApprovalThreshold` = 0 · daarna = leeg/null → 0 = elke offerte vereist goedkeuring;
null = geen drempel — **beide consistent**." De twee toestanden moeten dus uit elkaar te houden zijn
in de UI, en het opslaan van een ander tabblad (Huisstijl, Inspecties, …) mag een veld dat niet op dat
tabblad staat niet wijzigen.

## Werkelijk
Twee problemen, met dezelfde oorzaak:

1. **`null` en `0` zijn in de UI niet te onderscheiden.** Staat de drempel op `NULL` ("geen verplichte
   goedkeuring"), dan toont het veld **Goedkeuringsgrens (€)** gewoon `0`. De helptekst zegt
   "Laat de grens leeg om geen verplichte goedkeuring af te dwingen", maar leeg is niet weer te geven —
   en dus ook niet opnieuw in te stellen via de UI.
2. **Opslaan van een willekeurig tabblad schrijft `quoteApprovalThreshold: 0` weg.** Elke "Opslaan"-knop
   (Huisstijl, Financieel, Inspecties, …) stuurt één `PATCH /organizations/:id` met het **complete**
   organisatie-object. Een `NULL`-drempel wordt daarbij als `0` geserialiseerd. Een beheerder die
   alleen de vier-ogen-toggle omzet, verandert daarmee ongemerkt de offerte-goedkeuringsregel van
   "geen drempel" naar "elke offerte boven € 0 moet door een Manager goedgekeurd worden".

Bijeffect van hetzelfde patroon: twee beheerders die tegelijk verschillende tabbladen bewerken
overschrijven elkaars velden (last-write-wins over de hele organisatie).

## Reproductie
1. Zet de drempel op `NULL`:
   `PATCH /organizations/:id  {"quoteApprovalThreshold": null}` → 200.
2. Verifieer: `SELECT quote_approval_threshold IS NULL … ;` → `t`.
3. Open in de portal **Organisatie → Instellingen → Inspecties**, zet één toggle om, klik **Opslaan**.
4. Verifieer opnieuw in de database.
5. Open het tabblad **Financieel**: het veld toont `0`, niet leeg.

## Bewijs
Onderschepte request-body van stap 3 (`fetch`-hook in de pagina):

```json
{"name":"InspeXi Demo","primaryColor":"#1e40af","defaultVat":9,"defaultValidityDays":14,
 "senderName":null,"senderEmail":null,"workdayStart":8,"workdayEnd":17,
 "inspectorPhoneDisplay":"INSPECTOR","inspectorEmailDisplay":"INSPECTOR",
 "inspectorStaticPhone":"+31 20 123 4567","inspectorStaticEmail":"klantcontact@inspexi-demo.nl",
 "quoteApprovalThreshold":0,"quoteApprovalRequiredRole":"MANAGER","chatEnabled":true,
 "inspectionReviewEnabled":true,"aiReviewEnabled":true,"aiReviewInstructions":null,
 "onlineRepairDefault":true}
```

Database vóór stap 3: `quote_approval_threshold IS NULL → t`
Database ná stap 3: `quote_approval_threshold = 0.00`, `is_null = f`

HTTP: `PATCH /api/v1/organizations/:id` → 200 (backend gedraagt zich correct; het is de client die 0 stuurt)

## Analyse / vermoedelijke oorzaak
De instellingenpagina houdt één formulierstate voor de hele organisatie en verstuurt die volledig bij
elke Opslaan-actie. `quoteApprovalThreshold` wordt als `number`-input gemodelleerd met een fallback
`?? 0` in plaats van `?? ''`/`null`, waardoor `null` bij het laden al 0 wordt.

## Advies
- Laat het drempelveld leeg blijven bij `null` en stuur bij een leeg veld expliciet `null` mee
  (het DTO accepteert `null` al: `@ValidateIf(o => o.quoteApprovalThreshold !== null)`).
- Verstuur per tabblad alleen de gewijzigde/eigen velden (dirty fields), zodat een tab-save geen
  onbedoelde velden overschrijft.
