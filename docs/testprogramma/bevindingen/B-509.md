# B-509 — Portal-routes zijn niet rol-gated: MANAGER krijgt een leeg org-instellingenformulier, ORG_ADMIN krijgt "Forbidden resource"

- **Testgeval:** OA-18 (waargenomen bij OA-01)
- **Actor / rol:** Manager / MANAGER en Org-admin / ORG_ADMIN
- **App:** Portal (:5173) · org: inspexidemo
- **Severity:** S3 (matig — geen datalek; verwarrende UX en een Engelse melding in een NL-UI)
- **Type:** autorisatie-UX
- **Datum/tijd:** 2026-07-27 13:55

## Verwacht
OA-18: "Probeer als ORG_ADMIN een SUPERUSER-route (`/organizations`, `/classification-models`) →
403/geen toegang." De backend doet dat correct. De portal hoort zo'n route dan niet te renderen, maar
een nette Nederlandse toegangsmelding te tonen — vergelijkbaar met de feature-gate, die het wél goed
doet ("Geen toegang — Deze functie zit niet in uw abonnement.").

## Werkelijk
De portal kent geen rol-gate op deze routes. Wie het pad intikt (of een oude bladwijzer opent) krijgt
de pagina te zien, waarna de mislukte request als tekst in beeld komt — half Nederlands, half Engels:

| Actor | Route | Wat de gebruiker ziet |
|---|---|---|
| ORG_ADMIN | `/organizations` | "Fout bij het laden van organisaties: **Forbidden resource**" |
| ORG_ADMIN | `/plans` | "Fout bij het laden van abonnementen: **Forbidden resource**" |
| ORG_ADMIN | `/classification-models` | "Fout bij het laden: **Forbidden resource**" |
| MANAGER | `/organization/settings` | Volledig **leeg maar bewerkbaar** formulier (Organisatienaam en Slug leeg) met een Opslaan-knop |

Het MANAGER-geval is het vervelendst: `GET /organizations/:id` geeft 403, de pagina rendert toch en
suggereert dat de organisatie geen naam heeft. (De backend blokkeert de bijbehorende `PATCH` wél met
403, dus er gaat geen data verloren — geverifieerd.)

De menu's zijn overigens wél correct gefilterd: een ORG_ADMIN ziet geen "Organisaties",
"Abonnementen" of "Inspectie-systeem" in de sidebar, en een MANAGER ziet onder BEHEER alleen
"Beschikbaarheid". Het gat zit dus puur in de route-guard.

## Reproductie
1. Log in als `manager@inspexi-demo.nl` op `http://inspexidemo.localhost:5173`.
2. Navigeer direct naar `/organization/settings` → leeg formulier.
3. Log in als `admin@inspexi-demo.nl` en navigeer naar `/organizations`, `/plans`,
   `/classification-models`.

## Bewijs
```
# MANAGER, /organization/settings
GET /api/v1/organizations/f765ff41-…  → 403 Forbidden
(pagina rendert; Organisatienaam en Slug leeg)

# MANAGER kan niet muteren (backend correct):
PATCH /api/v1/organizations/f765ff41-…  {"name":"Gekaapt"} → 403 "Forbidden resource"

# ORG_ADMIN
/organizations         → "Fout bij het laden van organisaties: Forbidden resource"
/plans                 → "Fout bij het laden van abonnementen: Forbidden resource"
/classification-models → "Fout bij het laden: Forbidden resource"
```
Geen 500, geen witte pagina, geen onafgevangen JS-fout.

## Analyse / vermoedelijke oorzaak
In `App.tsx` zijn deze routes wel lazy-loaded maar niet in een rol-guard gewikkeld (er bestaat al een
`FeatureRoute`-patroon voor entitlements; een `RoleRoute`-equivalent ontbreekt). De pagina's tonen de
ruwe `error.message` uit de API — die voor RolesGuard-403's Engels is (zie **B-106**).

## Advies
- Wikkel SUPERUSER-only routes (`/organizations`, `/plans`, `/classification-models`, `/norm-types`,
  `/measurement-sheet-templates`) en ORG_ADMIN-only routes (`/organization/settings`, `/users`) in een
  rol-guard die dezelfde "Geen toegang"-pagina toont als `FeatureRoute`.
- Vertaal de 403-melding client-side naar NL in plaats van `error.message` door te geven.
