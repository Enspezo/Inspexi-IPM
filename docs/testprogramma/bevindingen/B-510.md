# B-510 — Entitlement-afhankelijke org-vlaggen (`aiReviewEnabled`, `onlineRepairDefault`) zijn via de API aan te zetten zonder abonnement

- **Testgeval:** OA-08
- **Actor / rol:** Org-admin / ORG_ADMIN
- **App:** API (:3001) `PATCH /organizations/:id` · org: inspexibasis (plan Basis)
- **Severity:** S3 (matig — geen functioneel lek, wél een inconsistente en misleidende toestand)
- **Type:** autorisatie / entitlements
- **Datum/tijd:** 2026-07-27 14:00

## Verwacht
OA-08: "`aiReviewEnabled` aanzetten **zónder** `AI_REVIEW`-entitlement → feature niet actief / nette
melding (**geen valse belofte**)." De API hoort de vlag te weigeren (403/400 "Deze functie zit niet in
uw abonnement") of hem hooguit als no-op te negeren — maar niet als "aan" te bewaren.

## Werkelijk
De portal doet het goed: op een org zonder entitlement staan de checkboxen **AI-voorcontrole
inschakelen** en **Online herstel standaard aan** disabled, met de tekst
"Niet beschikbaar in uw abonnement." (screenshot). Geen valse belofte in de UI.

De API kent die gate echter niet. Een `PATCH /organizations/:id` met `{"aiReviewEnabled": true}` van de
ORG_ADMIN van een Basis-organisatie levert **200 OK** en de vlag wordt opgeslagen. Daarna toont de
instellingenpagina een **aangevinkte** checkbox mét de tekst "Niet beschikbaar in uw abonnement" — twee
tegenstrijdige signalen. Functioneel gebeurt er niets, want de `/ai-review`-routes zijn
`@RequiresFeature('AI_REVIEW')`, maar de administratieve toestand is fout en werkt door in de publieke
by-slug-branding (`aiReviewEnabled: true`), die de portal gebruikt om UI te tonen.

## Reproductie
```bash
BA=$(login admin@inspexibasis.nl inspexibasis)   # plan Basis, geen AI_REVIEW / ONLINE_HERSTEL
ORGB=ba48765a-6dcc-40b0-a631-7f9e74d88c53

curl -s -H 'Host: inspexibasis.localhost' -H "Authorization: Bearer $BA" \
  http://localhost:3001/api/v1/organizations/me/features
# → ["BASIS_CRM","BASIS_UITVOERING","BASIS_INSPECTIES","BASIS_WORKFLOW"]

curl -s -X PATCH -H 'Host: inspexibasis.localhost' -H "Authorization: Bearer $BA" \
  -H 'Content-Type: application/json' -d '{"aiReviewEnabled":true}' \
  http://localhost:3001/api/v1/organizations/$ORGB
# → 200 OK, "aiReviewEnabled":true
```
Open daarna `http://inspexibasis.localhost:5173/organization/settings` → tab **Inspecties**.

## Bewijs
- `GET /ai-review/status` → `{"available":false,"model":"claude-sonnet-4-6"}` (geen `ANTHROPIC_API_KEY`)
- `PATCH … {"aiReviewEnabled":true}` → **200** (verwacht: 403/400 met NL-melding)
- UI-state ná de PATCH: `{"l":"AI-voorcontrole inschakelen","checked":true,"disabled":true}` naast de
  tekst "Niet beschikbaar in uw abonnement."
- Screenshot: `bevindingen/img/B-510-ai-toggle-zonder-entitlement.png`
- De vlag is na de test weer op `false` gezet (geverifieerd in de database).

## Analyse / vermoedelijke oorzaak
`OrganizationsService.update()` schrijft de vlaggen ongefilterd weg; er is geen
`EntitlementsService.assertFeature('AI_REVIEW' | 'ONLINE_HERSTEL')` in het update-pad. De gate leeft
alleen op de functionele routes en in de React-componenten.

## Advies
Valideer in `update()`: wordt `aiReviewEnabled`/`onlineRepairDefault` op `true` gezet, dan eerst
`assertFeature(...)` — bij ontbreken een 403 met de bestaande NL-tekst "Deze functie zit niet in uw
abonnement". Overweeg de vlaggen bij het downgraden van een plan automatisch op `false` te zetten.

## Kanttekening (SKIP-deel van OA-08)
Het inhoudelijke deel van OA-08 — daadwerkelijk een AI-voorcontrole laten draaien en beoordelen wat de
UI belooft versus wat er gebeurt — is **niet uitgevoerd**: er is geen `ANTHROPIC_API_KEY` geconfigureerd,
`GET /ai-review/status` geeft `available:false` en de run-endpoints geven 503. Dat deel staat in het
logboek als **SKIP**.
