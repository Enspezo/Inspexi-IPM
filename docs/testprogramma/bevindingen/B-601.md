# B-601 — Rate-limit-melding is Engels, behalve bij de enumeratieguard

- **Testgeval:** SEC-19, SEC-20a, SEC-20b, PUB-15 (contrast met SEC-21)
- **Actor / rol:** elke gebruiker, ook anonieme klanten
- **App:** API (:3001) — geraakt de portal (:5173), client-portal (:5174) en PWA (:5176)
- **Severity:** S4 (cosmetisch, maar wel zichtbaar voor eindgebruikers)
- **Type:** grenswaarde / UX-consistentie
- **Datum/tijd:** 2026-07-27 14:5x

## Verwacht
Foutmeldingen zijn in het Nederlands en begrijpelijk voor de eindgebruiker — dat is het orakel uit
§3 van het masterplan en de projectconventie (UI-teksten en validatiemeldingen in het Nederlands).
Bij een rate-limit hoort dus iets als "Te veel pogingen, probeer het later opnieuw".

## Werkelijk
Drie van de vier gethrottlede routes geven een onvertaalde framework-melding:

```json
{"success":false,"message":"ThrottlerException: Too Many Requests","statusCode":429}
```

Dit geldt voor `POST /auth/login` (10/min), `POST /client/repair/lookup` (5/min) en
`POST /client/auth/magic-link` (20/min). De term "ThrottlerException" is bovendien een
implementatiedetail dat niets zegt tegen een klant die zijn rapportnummer intypt.

De **enumeratieguard** doet het wél goed:

```json
{"statusCode":429,"message":"Te veel pogingen, probeer later opnieuw"}
```

Juist bij de herstel-lookup is dit pijnlijk: dat is een pagina voor anonieme herstellers — vaak een
monteur op locatie — die na vijf pogingen een Engelse stacktrace-achtige term voorgeschoteld krijgt.

## Reproductie
1. Start de API zónder `NODE_ENV=test` (throttling actief)
2. Vuur 6× achter elkaar:
   ```bash
   curl -s -X POST -H 'Host: inspexidemo.localhost' -H 'Content-Type: application/json' \
     -d '{"referenceNumber":"RAP-TEST-100","postalCode":"9999ZZ"}' \
     http://localhost:3001/api/v1/client/repair/lookup
   ```
3. De 6e respons is 429 met de Engelse melding
4. Vergelijk met 4× een onbestaand subdomein → Nederlandse melding

## Bewijs
- HTTP 429 + `Retry-After: 60` op login/lookup/magic-link, body zoals hierboven
- HTTP 429 + `Retry-After: 300` op de enumeratieguard, mét NL-melding
- Volledige meetreeks in `bevindingen/logboek-THROTTLE.md`

## Analyse / vermoedelijke oorzaak
`AppThrottlerGuard` laat de standaard `ThrottlerException` van `@nestjs/throttler` doorlopen; alleen de
`EnumerationGuard` gooit een eigen `HttpException` met een Nederlandse tekst. De exception-filter
vertaalt de message niet.

Dit hoort bij hetzelfde patroon als **B-106** (RolesGuard geeft "Forbidden resource") en **B-155**
(framework-defaults zoals "Unauthorized" en "Validation failed"): overal waar een guard de standaard
Nest-exception laat vallen, verdwijnt de Nederlandse laag.

## Advies
Override de melding centraal in `AppThrottlerGuard` (`throwThrottlingException`) met dezelfde tekst die
de enumeratieguard al gebruikt: *"Te veel pogingen, probeer het later opnieuw."* Dat lost alle
gethrottlede routes in één keer op. Overweeg tegelijk de bredere aanpak uit B-106/B-155: een
exception-filter die bekende framework-meldingen naar het Nederlands mapt.
